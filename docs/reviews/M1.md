Reviewer: independent M1 review agent, 2026-10-21, `main` at `72a787a` (branch `review/M1`).

- Independent references (double precision / uint32 phase, written from the patch text, not from the engine code: [`M1/fmref.py`](M1/fmref.py), [`M1/echoref.py`](M1/echoref.py), [`M1/zdf.py`](M1/zdf.py)) against the committed goldens.

- Four parallel deep reads of graph, dsp, engine and jit, each confirming its findings with probes. I re-ran the Critical/High ones.
- I didn't run `pqdaw --play` (it plays on the user's speakers). The latency path was reviewed in code only.

## Summary verdict

M1 is a serious, mostly well-built engine core, and its numbers are better than I expected.
- **Engine semantics hold up against independent references.** The committed goldens match an independent double/uint32 reference written from the patch text alone:
  - `fm_voice` and `fm_voice_arp` (voices, sample-accurate onsets, atom ADSR, through-zero FM): max |Δ| 7.0e-5 and 4.6e-5.
  - `stereo_echo` (cross-coupled delay loop in sub-blocks): 1.9e-5.
  - `drive_zdf` (per-sample Newton): median 2e-6.
- **The JIT is fast and faithful.** The proto-Operator at 64 voices renders at 20.5× realtime on the JIT, about **4.9 % of a core**, so SPEC §13's "< 10 %" target is reachable before T1b.2's voice-SIMD work. JIT output was bit-identical to the interpreter on that patch.

The problems are concentrated in three places:
1. **The scheduler's buffer reuse still has siblings of the T1.7 bug.**
   - The last op of a solve body overwrites an equation operand or unknown that the solver reads afterwards.
   - The last op of a voice stage overwrites a voice `out` that the engine reads afterwards.
   - A multichannel delay line inside a feedback loop gets the wrong read inputs from channel 1 on.

   All three silently produce wrong audio on **both** backends, so the interpreter-vs-JIT tests can't see them. The reference-evaluator corpus never has a solve whose equation sides share a buffer, or two voice outputs.
2. **Voice semantics have real holes.**
   - Idle lanes (hz 0) poison the whole instrument mix with NaN.
   - Abutting same-pitch notes never re-attack.
   - Same-Hz unison notes collapse into one voice, which breaks SPEC §5 JI objects.
   - `voice_last` drops to 0 when the last voice ends.
   - Dropped NoteOffs can leave stuck notes.
3. **Architecture risks for M3/M4 that are cheap to decide now and expensive later.**
   - Compile granularity: SPEC §7.4 flattens the whole project into one program. Measured: about 0.6 ms of JIT time per op, the interpreter 5× slower than the JIT, and the crossfade doubles CPU. So every structural edit in a large project means seconds of whole-project interpretation plus a doubled-CPU fade.
   - Text edits lose every state key (Q68).
   - Internal reducers can't fade (Q61).
   - There is no plan at all for SPEC §7.7 silence/sleep.

There's also one memory-safety bug: a large delay `max` overflows `stateBytes` and corrupts the heap. The JIT's default `contract` makes the backends diverge without bound in feedback loops, contrary to Q64.

Process: the tasks' literal acceptance criteria are met almost everywhere. Two places don't hold up:
- Several orchestrator verifications ran test subsets rather than the full dev + release suites.
- A few PROGRESS, RESULTS and QUESTIONS statements are not what the code does: the JIT "forward AD", constant folding "bit-identical", and Q64's "~1e-7, far below audibility".

Checked and found correct (no finding):
- **Phasor uint32 claim.** The increment is `round(hz · 2^32/sr)` in double, round-to-even, identical on S1/S8. ±sr/2 → 0x80000000 is harmless. The output is top-24-bit truncation, max 1 − 2^-24, never 1.0. The in-register prefix sum and the time-vectorised constant-hz path are exact. Level-sensitive reset is applied before emit. The 10^9-sample drift test is trivial by itself, but `exactIncrement` independently checks the rounding.
- **Delay lines.** Linear/Hermite/allpass formulas and minimum clamps are correct. Ring headroom is sufficient, and NaN/inf delays are clamped.
- **Noise.** Block-partition independent; decorrelated lanes and groups.
- **Optimiser exactness.** `x/2^k` is gated on normal reciprocals; signed-zero rules, `pow(x,2) → x·x` (negative/NaN), literal mux, min/max operand order, no voice → global replacement, CSE never on stateful nodes.
- **Inference.** Reducers inserted once per boundary, the bool eq/ne rewrite, declared bounds, state-key hashing (injective in NodeId path; inserted nodes stateless).
- **Scheduler.** Broadcast/loop pinning (Q55 fix), multi-output in-place restricted to output 0, perGroup exclusion, reducer accumulators, chained-delay sub-block minimum, state offsets kept/holes first-fit/compaction.
- **JIT.** No `fptosi`/`fptoui` (all conversions are x86 intrinsics with the kernels' out-of-range results). Only `contract` + `afn` set, cleared in Newton blocks. min/max as compare-select with the kernels' NaN operand order. Inlined stateful atoms bit-identical under NaN/±inf/±30 kHz/huge inputs at blocks 64/37/1. Images outlive the Compiler. Runtime helpers are allocation- and lock-free. MXCSR untouched (relies on the caller's DenormalGuard, documented).
- **Hot swap.** Plans are built against the last published image, with FIFO and no swap during a fade, so the plan's source is the replaced image. A failed publish leaves `last_` intact. The audio thread never frees. QSBR ordering is right. The crossfade is bit-exact where old == new. Param remap by key.
- **Voices.** Delay-ring re-alignment on compaction preserves age exactly. Steal fade arithmetic and deferred starts. Event frame clamping. Block-size invariance of a forced-steal render (64 vs 128: identical).
- **Interpreter.** Bounded loops; NaN → default; clamping (`/fp:precise` keeps `v != v`); oversize blocks zeroed.
- **WAV writer/reader** (fmt 18 + fact, extensible > 2 ch, 64-bit 4 GiB guard). **RtLog push and the ASIO/WASAPI callback paths**: no allocation or locks found.
