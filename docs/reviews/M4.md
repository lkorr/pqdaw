## Summary verdict

M4 delivers a lot, and the parts that were measured are good:
- **EQ Eight:** every filter type matches an independently derived RBJ/bilinear response within ≤ 0.005 dB at five sample rates.
- **Utility:** bass mono is an exact LR4 crossover (≤ 0.003 dB, −6.02 dB at the crossover).
- **The M3 review is almost entirely fixed.** 38 of its findings are fixed, including C1 and H1–H8. Its probes pass: mixer/solo 14/14, mute lanes play, a held boundary generator gives automated == static at 300.5294 Hz, and an anchored fifth holds 701.8–702.0 ¢ through a sweep.
- **The code reads show a sound architecture:** stable NodeIds from document ids, inline rack lowering, a macro as a single param write, epoch-reclaimed images, a seqlock TapRing.

The problems cluster in four places:

1. **Two memory-safety bugs on code read (H1, H2), neither reproduced.**
   - Moving a device from a group into its child track uses a freed `Track&`.
   - The cost-label path frees a `CostMeter` on a 10 s wall-clock timer while an image held by the interpretBudget logic can still write through it on the audio thread.
2. **A device-sound bug users will hit at once (H3).** EQ Eight's 48 dB cuts put the Q-dependent resonance in all four sections:
   - +33 dB at Q 2;
   - +105 dB at Q 18 (rendered).

   The T4.10 test couldn't catch it because it compares against the same law.
3. **Device functionality that is marked done but isn't reachable or usable:**
   - Auto Filter is not in the stock device library, so no user can add it (H5).
   - No device parameter, macro or wire amount can be automated, and no task plans it (H4).
4. **Gates and process.**
   - The M4-prep gate is `[x]`, but its acceptance criterion (the 30-track fixture at ≤ 25 % of the block period on the JIT) was never met: the best recorded figure is 37 %. Its M17 item (split `ViewContext`, a shared auto-scroll layer) was not done (H6).
   - T4.15 changed the optimiser and merged with no release run.
   - No whole-suite run has been recorded since 2026-10-26.

   That makes the boundary runs this review could not do more important than usual.

Every M4 golden was viewed at 1.0 (the SVF core also at 1.5×), plus my own captures [`audio-rack-1000x700.png`](M4/ui/audio-rack-1000x700.png) and [`operator-1.25x.png`](M4/ui/operator-1.25x.png). Contrast was sampled from the pixels:

- circuit node labels about 4:1;
- deactivated device text 2.7–3.0:1, intentional and Live-like.

Not seen: 2.0×, the morph animation, live cursors, 36+ tracks.

**What works.**
1. **The device frames read as Live:** the title bar with amber activator, fold triangle and "Default" preset slot; compact panels; arc knobs with the value below; dark value fields. Utility, Saturator, EQ Eight and Auto Filter are recognisable at a glance. Operator at 1.25× (the screenshot) is a faithful, well-proportioned port: the oscillator rows, the envelope display with draggable points, the algorithm grid and the partial editor.
2. **EQ Eight's display is the strongest panel:** numbered dots, the selected band filled, the spectrum behind, glyph choosers.
3. **The rack frame has the right parts:** the M/C/Z/Map/Rnd/Var strip, macros, the chain list with solo/volume/pan, a zone editor with fades, and the chain contents beside it.
4. **The circuit symbol sheet is clean and conventional:** ANSI gates, op-amp triangles, z⁻¹ boxes, filter glyphs, wires styled by rate. The T4.15 tooltips ("= 4/27", the reason a node is inactive) and inactive-hiding (Saturator 84 → 13 nodes) are excellent.
5. **The cable look** in `device-wiring.png` works: beziers, a z⁻¹ badge on the loop, live range rings.

**What doesn't (concrete changes, most valuable first):**
1. **Make the circuit editor readable on first open (M15).** Open at Mid zoom on the outputs, keep terminal names at every LOD, number the mux inputs and light the active one, and collision-cull the cost labels. Today, the editor opened from a device shows no readable text until you zoom in.
2. **Racks.**
   - Give the zone editor an axis and hover values (M16).
   - In the 1000 × 700 capture, Macros 5–8 sit as empty 0-valued knobs in a 2 × 4 grid taking half the frame, and the chain selector is a macro-panel knob ("Chain 52"). Live hides unused macros (Live 12 shows a variable count) and keeps the selector in the zone editor.
   - The text buttons (M C Z Map Rnd Var) read as debug controls next to Live's icons.
3. **Fill the Device view's height.** Panels stop around 200 px of a 240–300 px detail area, leaving a dead band below (both captures). Stretch the frame background to the detail height as Live does.
4. **Project patch view at overview zoom (L13):**
   - label every block;
   - hide pin stubs below Near;
   - route modulation wires in the gutters between bands;
   - use a light alpha of the track colour, not a grey blend.
5. **The generic panel (L12):** it is the first panel every new MIDI track shows, so it should look as good as the stock ones.
6. **Discoverability:**
   - an "Open in Circuit View" glyph in each title bar;
   - a Create > Device / Audio Effect Rack / Instrument Rack section;
   - jack names on hover;
   - status hints for Map mode and jack drags;
   - an Edit menu that follows the focus (M14).
7. **Text pane:** a monospace face (Q124: none yet), soft wrap, readable line numbers, the error on its own line (L14).
