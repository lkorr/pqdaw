## The two note worlds (user caveat)

No MIDI notes internally. (1) **Keys** = degrees of a tuning, stored as `PitchKind::Degree` (follow tuning signals / MOS
morphs, Degree key zones). (2) **Hz** = instruments built on `voice.hz`, stored as `PitchKind::Cents` (exact, no 128-key
limit).

Each track gets `doc::NoteInputMode {Keys, Hz}` (on `Track`). Every incoming key (MIDI port or computer keyboard) goes
through ONE pure map `doc::InputPitchMap`, built off-thread from `effectiveTuningRef`:
- Keys: MIDI key k → absolute degree `k − 60` (key 60 = degree 0, equave 0); a Scala .kbm (`tuning::mapKey`) wins and
  unmapped keys are ignored. Result = Degree PitchId + resolved Hz, PitchSource, noteDegree — exactly what
  `resolveTrackPitches` gives a drawn note, so a live note sounds identical to the drawn one, tuning-as-signal included.
- Hz: the same key → that degree's Hz in the track's tuning × bend at note-on, stored as `PitchId::fromCents`,
  `PitchSource{}`.
- Bend while held always moves the sounding voice (`notePitch`); stored = identity at note-on (curves are M7).
- Raw data never lost: the capture buffer keeps (port, channel, key, velocity, bend, timestamp) beside the identity.
- Computer keyboard produces degrees directly (equave offset), through the same map's degree path.
Flat table 128 × {PitchId, hz, PitchSource, noteDegree} published as an immutable image: one indexed load per event.

## Decisions taken (orchestrator, most reversible; logged as questions)

- RtMidi 6.0.0, tag archive pinned by SHA-256, WinMM only (`RTMIDI_API_WINDOWS_MM`), linked by `pq_app` only, wrapped in
  `app::MidiInputService`; the engine never includes RtMidi.
- Timestamps: QPC in each RtMidi callback; `CallbackRunner` records QPC per callback → engine time ↔ QPC two-point map.
  Monitoring schedules at stamp + one device period (constant latency, no jitter). Recording uses the stamp minus the
  audible output latency.
- Recording latency offset = driver in + out latency + BlockAdapter latency + PDC total of the monitored path + manual
  offset (prefs, ms, signed). Notes use the output part only.
- Recordings: 32-bit float WAV, `<project>/samples/recorded/<track> <yyyy-mm-dd hh-mm-ss> <input>.wav`; one continuous file
  per input per record pass; loop takes reference regions. Unsaved project: `%LOCALAPPDATA%\pqdaw\Unsaved\<session>\samples\recorded`,
  moved on first save, deleted on discard after confirmation.
- Take lanes ordered under the track; a pass appends one; main lane = the comp. Comping copies a region of a take into
  the main lane as an ordinary clip with provenance (`ClipSlot::take`), non-destructive, auto-crossfade
  (`AudioClip::crossfadeIn`). Auditioning a take = a Sequence change, no compile.
- Overdub (notes): off → each pass a take; on → merge into the main-lane clip (one undo step per pass).
- PDC compensates audio routing (tracks → groups, sends → returns, → master, track → another track's mixer cables) AND
  sidechains (they're audio). Cross-track modulation wires stay undelayed (§15 2026-10-24). Each unit's automation and
  note events shift by its input latency. Fractional latencies compensated to the nearest integer sample.
- Metronome + count-in in the engine after `ProjectProgram`'s output, before the device copy; click delayed by the master
  PDC total; synthesised; never in offline renders for M6; main pair by default, cue pair optional.
- Warp markers map content ticks ↔ source frames (piecewise linear); the clip player's law becomes segment-wise.
  Default warp for new clips stays Off; pref "Auto-Warp long samples" (off by default) uses Beats; recorded clips Off.
  Complex = signalsmith presetDefault; Complex Pro = + formant preservation (Formants %) + Envelope. Transpose applies to
  every mode except Re-Pitch.
- Keys mapping default = consecutive degrees (option "12-TET nearest" per track); Hz source default = the key's pitch in
  the track's tuning (option "12-TET A4=440 + bend").
- Computer keyboard: Live's letter rows → consecutive degrees (17 keys), Z/X equave, C/V velocity ±20; `M` toggles (M8
  macro mode will replace the scope when active).

### T6.2 PDC: units report latency, readers delay their inputs
`graph` (new `latency.h/.cpp`, `atoms.cpp` latency rule + new `latency` atom), `engine` (`project_program.h/.cpp`,
`project_compile.h/.cpp`, new `latency_plan.h/.cpp`), `app` (new `project_link_latency.cpp`, `project_link.h` members);
ARCHITECTURE "Per-track compile units", PATCH_LANGUAGE. Depends: —. Lane A, phase 1.
- Reporting: after infer, `graph::pathLatency(const TypedPatch&)` → per root out slot frames (double): longest path from
  sources (root ins, voice sources, clipPlayer, track.in) to each out/export, weighted by a new atom-table `latency`
  property (rule like `rules::delayLinear`); oversample converters weigh `groupOversampleLatency(factor)`. New atom
  `latency(x, frames: const)` = pure delay that reports (user lookahead devices; M9 Limiter). `z1`/`delay*` report 0.
  `CompiledUnit`/`UnitImage` gain `outLatency` and `inLatencyTo`. PF.1's cache key excludes them.
- Plan (pure, non-RT): `engine::CompensationPlan planCompensation(const ProjectLayout&, span<const UnitLatency>,
  span<const int32_t> trackOffset)` in unit (topological) order: `A_u` = max over audio input buses of L(bus); each input
  bus delay = round(A_u − L(bus)); produced bus L = A_u + outLatency; master L = PDC total. O(units + bus reads).
- Apply (RT): `ProjectProgram::setCompensation(plan)` via ring like `publishTopology`, taken at an image-block boundary. A
  delayed reader input gets a preallocated pow2 ring; at the start of the reader's `runUnit` push the bus, point
  `Packet::inPtrs[k]` at the delayed read. Silent flag = bus silent for the last delay + N frames (idle units still idle).
  Delay changes crossfade old/new taps over 10 ms. PF.5-safe: the delay belongs to the reader, runs in its slot after
  its producers; no new DAG edge, no shared state.
- Intra-unit sums (merged by sidechain/modulation/SCC): `ProjectCompileOptions::internalDelays` (wire → frames) from a
  first pathLatency over the members; `composeUnit` inserts `latency` nodes on internal Audio wires. Only misaligned
  merged units pay a second infer.
- Time shift: `Timeline::setSlotLatency(k, A_u)` published with the plan; events for slot k generated for `[t − A_u, …)`,
  automation targeting unit u evaluated at `t − A_u`.
- `ProjectProgram::outputLatency()` (atomic) → views, recorder, metronome.
- Accept: impulse tests (NullDevice, offline): two parallel tracks into a group, one through 4× oversampling → aligned
  (≤ 0.5 sample for fractional); sends → return → master, 3-deep nested groups, `latency(x, 480)` on 1 of 64 tracks →
  all aligned, master total 480; toggling oversampling while playing → diff vs steady ≤ −60 dBFS outside the 10 ms window;
  no-latency project bit-identical to main (no rings); automation/notes on a compensated group shift by A_u (gain step
  test); merged sidechain unit aligns internally; RtScope on runUnit with delays and on a plan swap; wholeProject() vs
  per-unit agree.
- Verify: `-Affected -Slow` + ship link `pq_bench_dsp`. CPU: zero without latency; ≤ 1 copy + 1 read per channel per
  block per compensated input (≤ 40 ns stereo @64, release); plan ≤ 50 µs @128 tracks, recomputed only on a latency change.

paths into every sum (groups, sends, returns, master, sidechains); automation and notes shift with them; cross-track
