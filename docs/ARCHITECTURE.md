# pqdaw architecture

This document fixes the module layout and the interfaces between modules so that several agents can work in parallel without colliding. [SPEC.md](../SPEC.md) says *what* to build. This file says *where it goes and how the parts talk*. If an interface here has to change, change this file in the same commit and log it in `docs/PROGRESS.md`.

## 1. Modules and dependency direction

```
                    ┌──────────┐
                    │   app    │  pqdaw.exe: wires everything together, CLI flags, main loop, TransportPort impl
                    └────┬─────┘
        ┌────────────────┼──────────────────┬─────────────┐
        ▼                │                  ▼             ▼
   ┌─────────┐           │            ┌──────────┐   ┌────────┐
   │  views  │ (T3.7)    │            │  engine  │   │  io    │ (inside engine/ for now: audio + MIDI devices)
   └──┬───┬──┘           │            └────┬─────┘   └────────┘
      │   └──────────┐   │                 ├────────────┬──────────────────┐
      ▼              ▼   ▼                 │            ▲                  │
   ┌─────────┐     ┌──────────┐            │        ┌───────┐              │
   │   ui    │     │ document │            │        │  jit  │              │
   └────┬────┘     └────┬─────┘            ▼        └───┬───┘              │

        │               └─────────────▶│ graph │◀───────┘                  │

        │                 ┌────────┐           ┌────────┐             └────┬────┘

        │                 └───┬────┘           └───┬────┘                  │

   ┌───────────────────────────────────────────────────────────────────────────┐
   │                                    core                                   │
   └───────────────────────────────────────────────────────────────────────────┘
```

Arrows point at dependencies. A module may only include headers from modules below it. **No cycles.** `jit` sits above `engine` (T1b.1): it produces `engine::ProgramImage`s, so it includes engine headers; the engine never includes `jit` — whoever owns the compiler worker (the app) hands compiled images to the engine (QUESTIONS Q63). `compile` (T1.x-arch2) sits above `engine` + `jit`: the one file → Schedule → image pipeline and the process's JIT compiler, used by `tools/pqc` and `app`. `ui` does not depend on `document` or `engine`. `views` (T3.7) composes `ui` + `document` (+ `tuning`, `core`) and never depends on `engine`: it reaches the transport through the plain-data `TransportPort` interface, which `app` implements (`ProjectLink` over the engine since T3.17; the wall-clock `SimulatedTransport` remains only as a fallback when playback cannot start). `app` depends on `views` + `engine` + `compile`. `document` depends on `graph` for the project → graph lowering (T3.17, `pq/document/lower.h`); it never includes `engine`. `media` (T5.1) depends on `core` + `dsp` only; `engine` depends on it (the RT read side of streaming is its header-only `pq/media/stream.h`; `pq/engine/wav_file.h` forwards to `pq/media/wav_file.h`), and `views` / `library` will (M5 plan).

## 2. Threads

| Thread | Realtime? | Owns | Talks via |
|---|---|---|---|
| UI / main | no | document snapshots, UI state, Vulkan | posts `EngineCommand`s (SPSC), receives `EngineReport`s (SPSC, lossy) |
| Audio | **yes** | the current `Program`, voice state, param blocks | lock-free only |
| Compiler worker | no | graph lowering, inference, optimisation, JIT | publishes `ProgramHandle` (atomic pointer swap + epoch) |
| Disk | no | sample streaming (T5.2: `SamplePool`'s disk thread, above normal priority; owned by whoever owns the pool, the app), recording writer | one ring per stream slot: the consumer claims / reads / releases lock-free; the disk thread polls the slots every 2 ms while engaged or while a stream is claimed and otherwise blocks on an event only non-RT code sets |
| Analysis | no | analysers (spectrum, scope, LUFS), indexer, transient/tempo detection | reads tap rings filled by the audio thread |

## 3. Key interfaces (sketches; the real headers are authoritative once written)

```cpp
// core: realtime-safe single-producer/single-consumer ring (power-of-two capacity; the producer- and consumer-written
// index blocks are kHotLineSeparation = 128 bytes apart, outside each other's adjacent-line prefetch pair)
template <class T, std::size_t HotLineSeparation = kHotLineSeparation> class SpscRing {
public:
  explicit SpscRing(uint32_t capacityPow2);  // allocates: construct off the audio thread only
  bool tryPush(const T&) noexcept;
  bool tryPop(T&) noexcept;
};

// core: allocation trap. In tests and debug builds, any heap allocation while an RtScope is active fails the test.
struct RtScope { RtScope() noexcept; ~RtScope() noexcept; };   // marks the current thread "realtime"

// core: RT log ring. One RtLog per realtime thread (SPSC of POD records: static "{}" format, code, ≤ 4 numeric
// args, rdtsc, sequence); RtLogger drains every 10 ms on its own thread, formats, writes lines; drops are counted
// exactly and reported as a line plus a sequence gap.
class RtLog { public: explicit RtLog(uint32_t capacityPow2); template <class... A> bool log(uint32_t code, const char* fmt, A...) noexcept; };
class RtLogger { public: void add(RtLog&, std::string name); void start(); void stop(); size_t drainOnce(); };

// tuning: everything resolves to float32 Hz in the end
namespace pq::tuning {
  struct PitchId;                                  // Degree | Ratio | Cents | Harmonic (SPEC §3.1)
  class Tuning;                                    // EDO | MOS | Scale | JI, with reference pitch (default C3 = 261.626 Hz)
  float resolveHz(const PitchId&, const Tuning&, const ResolveContext&) noexcept;
  class MosLinearTable;                            // per chain length n: (k_i, m_i) for every constant-order interval of g
  MosLinearSpan MosLinearTable::lookup(double g, double P) const noexcept;  // cents_i = k_i·g − m_i·P (+ equave·P), SPEC §3.3
  // T2.6 (pq/tuning/tuning_signal.h): an EDO / MOS tuning's per-interval coefficients rotated to its mode, plain data
  // for the tuning node's table (Scale, MODMOS and generator sequences have none: they play static pitches)
  Result<LinearTuningForm> linearTuningForm(const Tuning&);
}

// graph: the compiler pipeline
namespace pq::graph {
  class Patch;          // IR (pq/graph/patch.h): flat node/port/wire arrays, dense NodeIndex + stable NodeId,
                        // params with attrs, in/out/export declarations, subcircuit nodes, solve blocks, layout;
                        // validate() for structure + declared types; operator== is structural (ignores NodeIds/order)
  struct PatchFile;     // a .pqp file: imports + patches (pq/graph/patch_file.h)
  class AtomRegistry;   // leaf atoms + operators: name → signature (pq/graph/atoms.h)
  // pq/graph/parse.h. A file holds several patches. Options: externals (prelude signatures), an ImportLoader for
  // `import`s (graph does no file I/O), validate, previous (T1.x-text-ids: the previous parse of this text, whose
  // NodeIds the result inherits). parseDetailed() returns every Diagnostic (message, file:line:col, byte span) and,
  // with `previous`, ParseResult::idMatch; parse() formats them `file:line:col: error: …` + source line + caret.
  Result<PatchFile> parse(std::string_view source, std::string_view fileName, const ParseOptions& = {});
  ParseResult parseDetailed(std::string_view source, std::string_view fileName, const ParseOptions& = {});
  std::string print(const PatchFile&);             // parse(print(f)) == f
  // pq/graph/id_match.h (T1.x-text-ids, Q68): structural diff of a re-parsed patch against the previous one; paired
  // nodes take the previous NodeIds (names, then structure down inputs / up unique consumer edges, then Merkle-style
  // input hashes, then weak pairs whose atom/literal/ports changed), the rest get ids above every previous id. Dense
  // order is kept (it is text order: signatures and output order depend on it), so ids may become unsorted:
  // Patch::setNodeIds keeps an id → index table then (indexOf stays O(log n)). Patches pair by name.
  IdMatchStats inheritNodeIds(PatchFile& next, const PatchFile& previous);
  // T4.3, the stored layout (PATCH_LANGUAGE §2.2): layout lines name anonymous nodes by key (`y.in.a`: consumer key +
  // input; `_e<k>` roots under solve equations), so placing a node never changes how the rest prints.
  // ParseOptions::lenientLayout drops stale entries (ParseResult::layoutDropped) instead of failing; ParseResult::patchSpans
  // locate each patch's layout block. printLayout(patch) = the block print() writes; spliceLayout(source, parsed, laidOut)
  // = the source with only the layout blocks replaced (comments and formatting kept; byte-stable; line endings followed).
  std::string printLayout(const Patch&);
  Result<std::string> spliceLayout(std::string_view source, const ParseResult& parsed, const PatchFile& laidOut);
  // pq/graph/layout.h (T4.3): world units = logical px at zoom 1; inputs on a node's left edge, outputs on its right, pin
  // offsets from the caller's LayoutGeometry (views/circuit/symbols.h; defaultGeometry() for tools/tests).
  // autoLayout ("tidy"): feedback cut (per delay in a loop: its loop inputs or outputs, the fewer; then DFS) → layers
  // (longest path, then as late as possible; ins first, outs last) → shared dummy chains per output pin (forward) and per
  // reversed net → barycentric crossing minimisation (exact bilayer counts, best of N sweeps) → vertical placement by
  // isotonic regression per layer (dummy–dummy links ×4) → channel routing: one group per net per channel, groups ordered
  // by pairwise stub-crossing cost, packed into tracks keeping that order; writes NodeLayout and every wire's via points.
  // completeLayout: place unplaced nodes (auto positions moved off placed ones) + routeUnrouted (Z / detour, no
  // obstacle avoidance). carryLayout(next, previous): positions by NodeId after a text edit (T4.4).
  AutoLayoutStats autoLayout(Patch&, const LayoutGeometry&, const AutoLayoutOptions& = {});
  uint32_t completeLayout(Patch&, const LayoutGeometry&, const AutoLayoutOptions& = {});
  uint32_t routeUnrouted(Patch&, const LayoutGeometry&, float stub = 12);
  uint32_t carryLayout(PatchFile& next, const PatchFile& previous);
  // T4.4 (pq/graph/edit.h): the circuit editor's IR edits — connect (replaces the input's driver; a declared bool ↔
  // real mismatch is refused; a wire that would close a delay-free cycle runs through an inserted z1: the patch
  // language's rule is unchanged, the editor makes the delay explicit), addNode from a spec (literal with unit, atom,
  // operator, callee, `param` / `in` / `out` / `export` declaration), rename (declarations: the callers' signature copies
  // follow), constToParam (a param pin in place of a constant), makeSubcircuit (selection → new patch after the edited
  // one: ins, param pins from the parent's params, outs), refreshCallers (call nodes rebuilt by port name after a
  // signature change), anonymize (the printer's `_n<digits>` names treated as none). Parser support: ParseOptions::
  // deferMissingInputs (a missing call argument is a validation error, so unwired graphs print and parse back),
  // ParseResult::lowered (the file is whole; diagnostics are validation errors; NodeIds are inherited then too),
  // PatchTextSpans::begin (a patch's `patch` keyword), `export e` without a value; spliceLayout accepts a lowered parse.
  // T2.6 voice tuning: a `tune_voices(hz, cents)` node (no outputs, removed by infer) rebinds voice.hz (and, with
  // `cents` connected, voice.cents) in every subcircuit instantiated below its patch to those inputs; the binding
  // patch's own reads stay the engine's (the tuning node's fallback); the nearest binding ancestor wins.
  // pq/graph/infer.h (T1.3). Flattens subcircuits per call site (callees from InferOptions::library) and infers
  // kind/rate/poly/width with declared types as upper bounds. TypedPatch = { Patch patch (flat: no Subcircuit nodes,
  // inserted voice_sum reducers, bool eq/ne rewritten), types[] (inferred, parallel to patch.portTypes()),
  // stateKey[] (per node: hash of the NodeId call path, the hot-swap key), origin[], instances[] }. inferDetailed()
  // returns every Diagnostic, located at root-patch nodes via ParseResult::nodeSpans. T1.3-fix1 (Q29 B): free-running
  // sources (stateful, inputs global and ≤ param rate) that feed voice processing are per-voice
  // (InferOptions::freeRunningPoly = Voice, decided after the fixpoint; per-voice phasor/sine_hz get reset =
  // voice.trigger); `shared(expr)` in text sets Node::shared (an attribute, no node) and keeps its cone global.
  Result<TypedPatch> infer(const Patch&, const InferOptions&);
  // pq/graph/optimise.h (T1.4). Durations → samples (`· sr` inserted, TypedPatch::durationsInSamples), then a
  // fixpoint of constant folding (by the atom's own dsp kernel as Control regions run it: 8 lanes, lane 0; never
  // params), exact algebraic simplification, select sinking (pure ops below a select/mux when the copies drop below
  // audio rate), CSE (literals keyed by unit) and DCE; then rate refinement (pure atoms = max of their inputs' rates)
  // and a·b + c → muladd fusion at equal rates. Stateful nodes keep stateKey, atom and types; replacements never
  // change kind/width/poly (T1b.x-perf, Q132: a constant select / mux whose picked arm is a literal of another poly or width becomes a literal of the select's own type, so a structural switch's off section is dead). Errors: a folded channel index out of range; an `smp` literal through arithmetic into
  // a duration input. OptimiseOptions: sampleRate (sr folds when known), maxPasses, fuseMulAdd.
  Result<TypedPatch> optimise(TypedPatch, const OptimiseOptions& = {}, OptimiseStats* = nullptr);
  // pq/graph/schedule.h (T1.5). Tarjan SCCs on wires + implicit equation→unknown edges of solve blocks; feedback SCCs
  // become Loop regions with z1/delay split into read (in place) + write (loop end), run per sample or, when every
  // cut is a delay line with a constant lower bound, in sub-blocks of the shortest tap age (T1b.3: z1s are not cut
  // when cutting the delay lines alone breaks every cycle, so they keep the sub-blocks); a delay-free cycle is an
  // error (text) or gets a z1 + warning (ScheduleOptions::visualMode, Schedule::rewritten). Stages alternate global
  // (even, lanes 1) / voice (odd, lanes 8, run per voice group); a stage = Control region (param/const ops once per
  // block on 8-float patterns, param-rate solves) + Block/Loop regions. Global audio read by voice ops is broadcast;
  // voice reducers accumulate in the voice stage. Flat output: ops {kind, dsp kernel, lanes, Spl mask, operands
  // (Buffer | Param slot | Const | External), state entry, resource}, regions, stages, solve blocks, buffers (interval
  // reuse, in-place element-wise ops; the 100-node test chains need 1–2), params, externals, outputs, StateLayout. dump() is
  // the `pqc dump-schedule` text. Liveness counts reads after an op (solver lhs/rhs/unknown reads after a body,
  // engine voice-output reads at a stage end, a loop's next iteration) as keeping the value past that op;
  // ScheduleOptions::shareBuffers = false gives each value its own buffer (the replay checker, sched_replay.h, compares
  // the two). Loop sub-block bounds are evaluated in float32 like the runtime.
  ScheduleResult scheduleDetailed(const TypedPatch&, const ScheduleOptions& = {});  // + warnings in the Schedule
  Result<Schedule> schedule(const TypedPatch&, const ScheduleOptions& = {});
}

// jit (pq/jit/compiler.h, T1b.1): the LLVM backend: same ProgramImage ABI and results as the interpreter, bit for bit
// with the default options (T1b.1-fix1: no fast-math flags; CompileOptions::contract opts into fmul+fadd contraction,
// which a chaotic feedback loop turns into O(1) differences). One generated function per stage; element-wise runs
// fused into loops (8 frames per <8 x float> for global ops, one frame of 8 voices for voice ops; latency-bound runs
// interleave up to 8 independent chunks per iteration, capped by code size, and runs split past a size cap);
// per-sample loops, Control regions and solve bodies inline, including the simple stateful atoms; delay lines,
// wavetable, noise, shaper, sample_* and global stateful atoms in block regions call the dsp kernels; exact
// transcendentals call the kernels' own SVML functions (1 lane = lane 0 of the 8-lane call, Q94). Host CPU target
// (AVX-512 where present), a light IR pipeline by default, machine code at CompilerConfig::codeGenLevel
// (src/jit/src/codegen.h, compiler.cpp). CompileStats reports the object size and whether any stage needs stack
// probes (it must not: a frame > 4 KiB touches guard pages on the audio thread).
// Voice stages (T1b.2, CompileOptions::voiceCode, Q111): a voice value is one vector across voice lanes. The
// simple stateful atoms are inline in voice block regions too, and consecutive voice regions that run frame by
// frame (inline Block regions + per-sample loops) are fused into one loop over frames ("chains"); T1b.x-perf (Q122):
// global stages too, from the first to the last of at least two per-sample loops, with cheap Block regions between
// them (scalar per frame), one sleep segment, and at most 20 invariants + state words (more spill the recursions):
// independent recursions (EQ Eight L/R, M/S) overlap and cascades pipeline across frames. Every voice stage
// without sends or per-frame calls also gets a PAIR function (StageFn with group1/vstate1) that runs two occupied
// groups as <16 x float>: one zmm per value on AVX-512 hosts (VoiceCode::Pairs512, the Auto choice there), two ymm
// halves otherwise (Pairs256); a lone group runs the 8-lane function. Its stage-local voice values have a second copy
// for the second group (HostLayout::altOff), kernel calls and reducers run once per half (second-group reducer
// records: ImageHost::reduceInfoB), exact transcendentals are one 8-wide SVML call per half: every mode is
// bit-identical to the interpreter (tests/jit voice-code cases). VoiceCode::ScalarLanes is the benchmark baseline
// (one voice lane per call, scalar code; refuses voice stages with calls). CompileStats::pairedStages.
// Smoothed gains (T4.x-fix-dsp): a global gain / gain_add with a param target is generated inline, so the device
// mixes it scales (EQ Eight's sections between their SVF loops, the Saturator's oversampled samples, Utility's
// matrix) stay in their chain / fused run. Before a run's (chain's, per-sample loop's) frames: per gain, if it is not
// steady (started, same target and time constant), a call to dsp::gainPrologue (the kernel's prepare / retarget);
// then one branch per block: every residual 0 → the loop with each gain as fma(x, target, acc) (a target of 0: acc /
// 0), else the loop with the kernel's per-frame definition (kernels_gain.cpp). The 1-lane kernel computes the same
// frame by frame, so interpreter == JIT bit for bit however the frames are split. Voice gains and audio-rate targets
// stay kernel calls.
```

`DeviceChangeNotifier` (wasapi_device.h, T3.18) is an `IMMNotificationClient`: endpoint added / removed / state / default changes call a function on a system thread (event driven, no polling); the DAW uses it as its generic hot-plug signal (USB interfaces with ASIO drivers have WASAPI endpoints too).
`Backend::Wasapi` is our WasapiDevice (the default); `Backend::RtAudioWasapi` keeps RtAudio's WASAPI for comparison and input. WasapiDevice's audio thread joins MMCSS "Pro Audio" once, waits on the device event, and per event runs the callback once per period on planar scratch, then converts once into the device buffer (no ring).
`Backend::Asio` is AsioDevice (T0.6-fix2): a clean-room host of the ASIO driver ABI (`asio_abi.h`; no Steinberg SDK). A control thread per device (COM STA, hidden window, message pump; it polls the request flags every 50 ms while the stream runs, 250 ms while a driver is loaded but stopped) makes every non-audio driver call and handles driver requests (reset / buffer-size / rate change → stop, dispose, release, reload, recreate, restart; latencies re-queried) that the RT-safe message callback only flags. The driver's thread calls bufferSwitch(TimeInfo) → convert inputs → CallbackRunner → convert outputs into the driver's half (float32 channels zero-copy) → outputReady(). One driver per process (the ABI's callbacks carry no context).
The engine's process entry will be an `AudioCallback` behind a `BlockAdapter`; `ProcessContext` frame counts are therefore always the fixed internal block on the realtime path.

### ProgramImage ABI (shared by interpreter and JIT)
- `ProcessContext` carries: frame count (≤ max block), sample rate, transport snapshot, pointers to input/output channel buffers, the parameter block (`float*`, indexed by `ParamSlot`), the event list for this block (sorted, preallocated), and the voice table.
- Concretely (pq/engine/program_image.h, T1.7): global signals planar (`frames` floats per slot: root `in`s, `out`s/`export`s, track.in, sidechain.in, send bus channels); voice signals per 8-lane group in the kernel layout (`frames · 8`, voices interleaved): `VoiceGroupIO { laneMask, signals[VoiceSignal] (voice.*), in[], out[], gain }` (T1.8-fix1: `gain` = the VoiceEngine's per-lane per-sample gain, frames · 8, or null; audio-rate `voice_sum` and voice sends add `select(gain ≠ 0, x, 0) · gain`, `voice_last` reads its lane only where gain ≠ 0, other reducers keep laneMask: Q61 option A), `VoiceTable { groups, numGroups, lastGroup/lastLane }`. Bools are lane masks everywhere. Param-rate inputs are read at frame 0. The image clamps params to their declared ranges every block (Q44). Slot meanings come from `io()` (`ImageInterface`: global/voice in and out slots with node, channel, rate; `ParamSlot`s; sample rate; maxBlockFrames; maxVoiceGroups). process() runs global stages once and voice stages once per group (`numGroups`) **whose `laneMask` is non-zero** (T1.8: a group without voices is skipped: its state holds, its voice outputs are not written; the JIT must do the same, so voice cost is per occupied group); reducers combine the groups' active lanes (per sample through `gain` when given); callers run it under `DenormalGuard` (CallbackRunner does). voice.* buffers as the VoiceEngine fills them: `Hz`, `Cents` (float) and `Gate`, `Trigger` (masks) are audio rate (`frames · 8`); `Velocity`, `Release`, `Ratio`, `Harmonic`, `UnisonCount`, `Index`, `Degree`, `Equave` (T2.6) are param rate, 8 floats only (frame 0). `ProcessContext::events` (`pq/engine/note_events.h`) is never read by an image.
- All Program state lives in **one arena** allocated when the image is built (plus one block per voice group for voice state). The state layout (`graph::StateLayout`, T1.5) maps `(TypedPatch::stateKey, channel, arena) → (offset, size, type tag, StateInit)`; the tag is (kernel, lanes, ring frames for delay lines). Hot swap copies state for every key whose tag and size match (SPEC §7.5). Given the previous layout, `schedule()` keeps every unchanged entry at its old offset (new entries fill holes, then append; compacted when holes exceed 2× the live size + 4 KiB), so the transfer is a few coalesced memcpys.
- Parameter values live in a double-buffered block written by the engine from `EngineCommand`s. Programs read them and never write them.
- **Inspection: live probes and cost meters** (T4.5, SPEC §7.3, §7.6, §11.1; `pq/graph/inspect.h`, `pq/engine/inspect.h`, `pq/core/probe_level.h`; QUESTIONS Q134). The general tap mechanism for any reader of a running program's values (the circuit editor's probes and LED trace now; T4.7's modulated-knob ring and T4.13's project patch view next). *Which value*: a `graph::ProbeTarget { path (NodeIds of the subcircuit calls from the root), node (NodeId), output }` names a node output as written; `InferOptions::probes` → `InferResult::probeSources` (the flattened output carrying it, through subcircuit boundaries, `in` / `param` pass-throughs, inserted reducers), `OptimiseOptions::valueMap` (where each flattened value ended up: CSE / folding forward it, a value fused into another op — a mul inside a muladd — or a dead one has none), `graph::probePoints(optimised, sources, valueMap, ids)` → `ScheduleOptions::probes` → `Schedule::probes` (`ProbeRef { id, value operand, poly, kind, stage (voice: the stage position), region (of the op that writes it), voiceSum }`). A probe only extends its value's liveness (a global value to the end of the block, a voice value to the end of its stage) and marks it stored in generated code; ops, regions, the sleep plan (value-based) and the state layout are those of the schedule without probes, so the audio is bit-identical with and without them (tests: every node output of the corpus probed, interpreter and JIT; interpreter == JIT probe streams). *Copies*: the shared image host copies each BOUND probe after the voice group of its stage (voice) or after the last stage (global) into its `TapRing` (the full signal; one relaxed load when nobody reads it) and/or `ProbeLevel` (last / min / max of the block; bools decoded to 0 / 1), between stages, never inside generated code; a voice value is the newest voice's lane (`VoiceTable` voice_last; 0 while none sounds) or the sum over the sounding lanes (`voiceSum`; bools: any); a global value whose region is asleep (T1.x-silence) reads 0. `ProgramImage::bindInspect(InspectBinding { ProbeTap { id, ring, level }[], CostMeter* })` (non-RT, before publish; images without a host return false). Cost: no probe compiled = the plain program plus an empty-list test per block; compiled but unread = one load per probe per block (bench/RESULTS.md T4.5). *Cost meters*: `engine::CostMeter` (owned by whoever publishes, outlives the images bound to it): while enabled and the image is the one last `attach`ed (`wants(key)`), `begin()` raises a flag word in aux (`Layout::meterFlagOff`), both backends read the TSC around every region they run — the interpreter around its region loops, the generated code around each region or fused voice chain behind the flag loaded once per stage function (`codegen.h`) — adding cycles and a timing count per region into buf (`Layout::meterOff`), and the host adds the block (and its total) to the meter after the last stage; disabled: one load per block and one predictable branch per region per block. `CostMeter::read` gives ns per frame per region and in total since the previous read of the same image (a new image takes a baseline first), less the measured cost of the TSC reads (`timerCost()`: per timing, from the region and from the total), with `units` (per region, the first region of its timing unit: a JIT chain is one) and the publisher's `tag` (`setTag`, e.g. the schedule generation). `graph::opCostWeight` splits a unit's time among its ops (an estimate where a region mixes subcircuits; exact per region). Measured: the meter's total within a few % of a benchmark of the same image (JIT; bench/RESULTS.md).
- **Silence and sleep** (T1.x-silence, SPEC §7.7; `graph::SleepPlan` in pq/graph/schedule.h, the host's "sleep" in pq/engine/image_host.h). *Declarations*: every atom says what silent inputs (exactly ±0) do to it (`dsp::silenceInfo`: Any / All / Clip / MulAdd, Memory with `dsp::silenceTail` = 1 for z1 and edge detectors, floor(max) + 3 for a delay line, Smoother for gain / gain_add), checked against its kernel (tests/dsp/test_silence.cpp); subcircuits inherit them through their atoms. *Plan* (`schedule()`, ScheduleOptions::sleep): Block / Loop regions of global stages are SLEEPABLE when, under H = "the segment's sources silent, its waking params unchanged, its state quiescent", every stateful op keeps its state (memory with a Z input, a settled z1 of a param-derived value, a settled smoother) and every value read outside its SEGMENT (the connected sleepable regions, joined also through always-running stateless ops) is Z (a greatest fixpoint, so feedback loops qualify); sources are root inputs, track/sidechain inputs and values of earlier stages (voice reducers), so the decision is made when the stage starts; each region lists the buffers it fills while asleep. *Run time* (the shared host, so both backends decide identically): at each global stage's start, per segment, scan its sources (an early-out backward scan; `ProcessContext::inSilent` answers for silent buses), compare its waking params, and, awake with silent sources, check its state — memory words ≤ ε, the frames a delay line wrote since the last look (once the whole reach after a swap) ≤ ε for its tail, smoother residuals exactly 0 — then flush the ≤ ε residue to 0 and sleep (ε = 2^-30 ≈ −180 dBFS on the state, ≤ −120 dBFS at the output through 60 dB of resonance / feedback gain: a feed-forward tail ends exactly, a feedback tail is cut there). The interpreter skips a sleeping region's records and zero-fills its fill buffers; the generated code branches once per region per block on the segment's flag word in aux (`Layout::sleepOff`) to the same fills (the constant-output kernel). Sources silent → it stays asleep, untouched; anything else wakes it for the whole block, so the first sample after silence is computed from the flushed state: identical to a run that never slept for feed-forward segments, within the −120 dBFS cut for feedback ones, identical to the Shadow mode (`SleepMode::Shadow`: same decisions, every region runs) in both cases, and interpreter == JIT bit for bit (tests/engine/test_silence.cpp, tests/jit/test_jit_silence.cpp). *ABI*: `ProcessContext::inSilent` (in), `outSilent` per global out slot, `tailsDone` (every segment asleep) and `dormant` (tailsDone, outputs silent, no voice group ran, nothing else in the image keeps state: `SleepPlan::dormantCapable`) (out); `ImageInterface::voiceTailFrames`; `ProgramImage::sleepStats()`. Images built with `SleepMode::Off` (InterpretOptions / jit::CompileOptions::sleep) never sleep.

### Voices and note events (engine, T1.8: `pq/engine/note_events.h`, `voices.h`)
- **Events**: `NoteEvent { frame, kind (NoteOn | NoteOff | Pitch | AllNotesOff | AllSoundOff), noteId, hz (float32, resolved upstream), velocity (note-on; release velocity for note-off), ratio, harmonic, unisonCount, unisonIndex, rampFrames, degree, equave (T2.6: a Degree note's identity for the tuning node, NaN = none), tuning (T2.6-fix3: which tuning node of the track patch the note follows, voice.tuning; 0 = none), flags (`kNoteEventRetune`: a Pitch event that also replaces the note's identity) — 48 bytes }`. `EventBuffer` (preallocated; RT-safe `push` keeps frame order, ties in push order; `clear`; when full it drops the newest NoteOn, then Pitch, and as a last resort merges offs into an AllNotesOff/AllSoundOff, never losing a note-off: T1.8-fix1) exposes an `EventList { events, count }` for `ProcessContext::events`. Producers (T3.16 sequencer, MIDI, JI objects) push events with frame offsets inside the block; a frame ≥ the block length is clamped. `Pitch` moves a note to a new Hz as a step or as a glide linear in cents over `rampFrames` (the hook for T2.6 and pitch curves).
- **VoiceEngine** drives one ProgramImage: `prepare(image, VoiceConfig)` off-thread; `process(ProcessContext&)` (RT-safe) allocates voices from `ctx.events`, renders the voice.* buffers, fills `ctx.voices`, runs the image, mixes each voice `out` slot as `Σ lanes select(gain ≠ 0, out) · gain` (`mix(i)`; an idle lane's NaN never gets in), ends voices and compacts. `VoiceConfig { maxVoices (polyphony; lanes above it are fade headroom: voiceGroupsFor(n) = ceil(n/8) + 1 groups), steal (Oldest | Quietest | None), retriggerSameNote, resetOnNoteOn, compact, stealFadeMs, silenceDb/silenceMs, releaseTimeoutMs, referenceHz (voice.cents), monitorMask, doneSlot (findVoiceSlot(io, patch, "done")), maxEventsPerBlock (NoteOn + Pitch per block; offs always apply), moveBudgetFrames (delay-ring frames compaction may move per block) }`. Inspection: laneStatus/laneOf/liveVoices/activeGroups/groupsRunLastBlock, signal(g, VoiceSignal), gain(g), stats().
- **Sample accuracy without sub-blocks**: an event at frame k changes the per-sample voice.* buffers at k (gate, trigger, hz, cents) and the lane gain (0 before the onset); param-rate voice signals take the lane's latest value for the whole block. A lane starting in a block has its state reset to StateInit at the block start (generic: per-lane words of every voice `StateEntry`, from a template built with `dsp::initState`; noise counters and delay-line headers are shared and kept; a delay line's ring is reset in O(1): `DelayState::start[lane]` = writePos, older taps read 0) and reads hz 0 until the onset, so its output from k on does not depend on block boundaries. A free lane reads hz = referenceHz (finite). Oversize blocks (> maxBlockFrames, refused by the image) still apply their events and voice ends.
- **Allocation**: best fit (a free lane of the fullest non-full occupied group, else the lowest empty group), plus compaction (`VoiceConfig::compact`, default on): at a block end, when the occupied groups exceed ceil(occupied lanes / 8), the least occupied group's voices move to free lanes of other groups (per-lane state words copied; the reachable part of a delay ring, min(history, ⌊maxDelay⌋ + 2) frames, re-aligned to the destination group's write position, at most moveBudgetFrames per block, else the group is not emptied; noise state stays with the group). This relies on the voice state layout rule of `atom_state.h` (per-lane fields are [8] arrays, word ≡ lane mod 8, first in each struct), which every backend's StateArena must keep; which bytes of each atom's state are per lane is declared per atom by `dsp::laneStateInfo` (M1 review L7: shared words are the noise counter, the delay header and phasor incScale/halfSr; a stateful atom without a declaration fails `tests/dsp/test_lane_state.cpp`, which also checks every declaration by running the kernel on lane-permuted inputs). Stealing above maxVoices: released before held, then oldest or quietest (peak of the monitored outs over the last block; voices younger than `quietestMinAgeMs`, still in their attack, only when every candidate is, M1 review L9); the victim fades (raised cosine) over stealFadeMs in its lane (engine-mixed outs and, through `gain`, internal voice_sum / sends) while the new note starts in a free lane; with no free lane it waits for the fade (deferred start at the next block's frame 0). Same-note retrigger (equal Hz) takes over only a released voice that started before this block and was released before the note-on's frame (a visible gate edge), without a reset; held voices are never merged (unison). NoteOff finds the newest held voice of the id, Pitch the newest held, else released; voice_last moves to the newest held/released voice when its lane frees or is stolen.
- **Voice end** (checked at block end): a `done` voice out/export (true or > 0.5 at the last frame), the monitored outs below silenceDb for silenceMs after release, or releaseTimeoutMs after release when there is neither. T1.x-silence: the image's `voiceTailFrames` (its voice stages' longest delay line) is the voice's tail: the silence window is max(silenceMs, tail), and a `done` with a tail starts the tail instead of ending the voice (it ends after its outs have been silent that long; without monitored outs, the tail's length after done), so an echo inside a voice is not cut. Internal `voice_sum` / sends / `voice_last` see the per-sample gain; voice_highest / lowest / loudest the block lane mask: QUESTIONS Q61.
- `ImageRunner::setVoices(VoiceEngine*, EventSource, capacity)`: the runner calls the event source per image block, then the VoiceEngine; an image without global `out`s plays the voice mixes (`pqdaw --play <instrument> --notes "60 64 67"`).
- **Image bindings (T1.9)**: everything image-dependent (voice out slots, mix buffers, lane reset/move spans, the image's voice state) is a `VoiceBinding`. `prepareLanes(io, cfg)` sets up lanes and voice.* buffers for a geometry (maxVoiceGroups, maxBlockFrames, sample rate); `makeBinding(image, doneSlot, monitorMask)` (non-RT) binds any image of that geometry; `attach(current, fadingOut)` (RT) switches at a block boundary, so lanes, notes and allocator state survive a program swap. While a crossfade runs, `process(ctx, fadeCtx)` runs both images on the same voice table, lane resets and compaction moves apply to both, `fadeMix(i)` holds the old image's mixes. `prepare(image, cfg)` = prepareLanes + makeBinding + attach.

### Hot swap (engine, T1.9: `pq/engine/program_host.h`, `state_transfer.h`)
- **ProgramHost** owns the running ProgramImage (any backend: it uses only the ABI). `publish(image, SwapPolicy{mode: Auto | Instant | Crossfade, fadeMs}, VoiceSlots)` (non-RT, internally serialised) builds everything that allocates — the transfer plan against the previously *published* image, the param remap (new slot ← old slot with the same `ParamSlot::key`), output scratch, the VoiceBinding — and pushes a packet through an SpscRing. The audio thread pops at most one packet per image block, never during a crossfade, so packets become current in publish order and each plan's source is exactly the image it replaces. Images must have the host's sample rate and maxBlockFrames (and voice geometry); `lastPublished()->stateLayout()` is the next compile's `ScheduleOptions::previous`. Device mapping as ImageRunner (one rule, `mapChannels`: input c → global root in c; output c ← c-th global `out`, mono on all, else the voice mixes). `HostConfig::externalVoices` runs the images through a caller's prepared VoiceEngine (renderOffline's); `takePending()` makes the first published image current before the first block (so its params can be set).
- **State transfer** (`buildTransferPlan` off-thread, `executeTransfer` RT): a new `StateEntry` takes the old entry with the same (stateKey, channel, arena) when tag and size match; else it keeps StateInit (`TransferPlan::matched/fresh/mismatched/dropped`). Ranges contiguous in both arenas are coalesced (with T1.5's stable offsets an edit is usually one range per arena). It runs on the audio thread at the swap, right before the new image's first block, from the old image's current state; voice ranges are copied per group, only for occupied groups when `resetOnNoteOn` (free lanes are reset at note start anyway), and not at all by a host without voices (`executeTransfer`'s `maxGroups` 0, M1 review L8). `ProgramImage::stateLayout()`/`stateArena()`/`io()` must be callable from the publishing thread while the image runs (they return immutable data / fixed pointers). State keys come from NodeIds: edits made on the Patch IR keep them; edited TEXT keeps them when it is parsed with the previous parse (`ParseOptions::previous`, T1.x-text-ids: ≥ 99 % — measured 100 % — of the corpus's state entries match after an added export, inserted lines, renamed bindings, reordered lines or a reprint); a plain re-parse renumbers nodes (declarations first) and loses the match (Q68). Every caller that re-parses text for a hot swap (pqc, a text editor view) should pass the previous parse; the document lowering builds IR with document-derived NodeIds instead (T3.17-fix2).
- **Swap at the block boundary**: audible (Auto) = transport playing, or any voice lane in use, or the last block's played output above `HostConfig::silenceDb` (−90 dBFS; read from the old image's scratch, no per-block metering). Audible → **linear** crossfade over fadeMs (clamped 5–20 ms): both images run on the same inputs/events/voice table, `out = old + g·(new − old)`, g = (k+1)/N, exactly `new` from g = 1 (bit-exact where old == new: an unchanged path passes untouched; linear because the two programs are correlated, equal-power would bulge up to +3 dB). Silent → instant. Params carried, VoiceEngine re-attached.
- **Reclamation**: the audio thread only advances an atomic "retired through" sequence (instantly, or when the fade ends) and calls `EpochReclaimer::quiescent` at the end of every `process()`; `collect()` (and `publish()`) retire those packets to the reclaimer, which frees them after the next quiescent state. The audio thread never frees. `audioOffline()/audioOnline()` while the stream is stopped.

- **Topology swaps** (T3.17, `ProjectProgram::publishTopology`, `ProjectCompiler::rebuild`): a track added / removed / re-routed changes the partition. `rebuild(graph, dirty)` re-partitions and REUSES every unit whose member tracks, bus connections (by bus key `"<track id>:<port>"`, `ProjectLayout::busKey`), input bus types and param links are unchanged and none of whose tracks is dirty: no compile (adding a track compiles the new unit plus the buses it feeds, e.g. master and the returns). `publishTopology(layout, units)` keeps the storage of every bus whose key and width are unchanged (so a continued unit's running image needs no rebinding), and the audio thread switches at one block boundary — run order, buses and every new image (T1.9 swaps: state transfer, crossfade when audible) at once, after the involved units' queued packets and fades are done. Removed units run on as zombies (in an order that still feeds their readers' old images) until every reader has finished the crossfade to its new image, so a removed track fades out instead of cutting off; then they are freed off the audio thread. Unit indices are those of the last published layout; `publish()` refuses while a topology is pending (`canPublish()`). Units whose member set changed (a merge, a split) start fresh.
- **Idle units** (T3.17-fix2, M3 review H1 "silence is free"; the unit-level start of T1.x-silence): `ProjectCompiler` proves per unit (`engine::idleAfterBlocks`) that its outputs are exactly zero while its input buses are silent and no voice sounds (zero propagation over the optimised patch) and that its only global state is smoothed gains with constant times; `UnitImage::idleAfterBlocks` = the blocks of unchanged params after which those gains have snapped onto their targets. The runner then skips such a unit in a block where every bus it reads is silent, it has no live voice and no note event, it is not fading and its linked params have been unchanged that long: bit-exact (running it would change nothing; tested against `idleUnits = false`), its bus channels are zeroed once and marked silent so readers can go idle too. A silent 64 × 8 project costs ≈ 0.4 % of a core (interpreted). The interpreter also skips a global Control region that reads only params and constants into buffers nothing else writes while the image's params equal the previous block's (the settled mixer's dB / pan math). **T1.x-silence** generalises the skip: a unit is also skipped while its image reported itself `dormant` after the last block it ran (every sleepable region asleep — the reverbs' and delays' tails done —, outputs silent, nothing else keeping state) and every bus it reads is silent, no voice, no event, no linked param change, no fade (bit-exact for the same reason; tested against `idleUnits = false`). A bus is marked silent by its producer's `outSilent` report (every slot writing it ±0; never during a fade) as well as by an idle producer, and the program passes the flags to its readers as `ProcessContext::inSilent`, so a silent project sleeps unit by unit downstream. `quiet()` also requires every live unit's `tailsDone` (no tail in progress). The idle 30-track stdlib reverb/delay project (tests/engine/idle_project_fixture.h) then costs bench/RESULTS.md's `pq_bench_silence` rows.
- **Bus meters**: `ProjectLayout::busMetered` buses get peak and mean square of channels 0–1 per block on the audio thread (one AVX2 pass); `readMeters(buses, levels)` reads them since the previous call (T3.17's track meters: the `"<id>:out"` buses).

### Timeline: transport, sequencer, automation (engine, T3.16: `pq/engine/timeline.h`, `sequence.h`, `automation.h`)

- **Images** (immutable, built off-thread): `SequenceImage::build` (per track a flat clip array sorted by start, overlaps trimmed (later wins, Q41); per clip a flat note array sorted by (start, id) with precomputed pass-0 / loop index ranges; unplayable notes dropped; 100k notes ≈ 2.6 ms), `AutomationImage::build`, `TempoImage`. `Timeline::publishSequence/Automation/Tempo` swap an atomic pointer and retire the old image to the timeline's own EpochReclaimer (`collect()`); the audio thread re-loads the pointers at every block start and is quiescent at the end of `process()`. T3.17-fix1: the audio thread keeps using its current images across blocks (and across a device stop), so it publishes which ones it holds (a hazard pair per kind: `cur`, and `cand` while it takes a newer one: store, re-read, bounded); a replaced image it still holds is kept back (`held_`) and retired once it lets go — before, an edit while the stream was suspended (the reader offline) freed the image the next block read.
- **Transport** (audio thread): commands `Play(t) / Stop / Continue / Locate(t) / SetLoop` through `post()` (SPSC, UI → audio) or `apply()`; reports `TransportReport { block, tick, songSample, bpm, loopWraps, playing }` through `poll()` (lossy SPSC, at most one per `reportEveryFrames` while playing, always after a command). Position = int64 song sample; each block plays ticks `[T0, firstTickAtOrAfterSample(P + frames))`, so a note at t sounds at exactly `ticksToSamples(t)` for any block size. Arrangement loop wraps at the exact sample `ticksToSamples(loop end)` (any number per block); a new tempo map keeps the musical position. `snapshot()` (TransportSnapshot for `ProcessContext::transport`) describes frame 0.
- **Sequencer**: per track a cursor (clip, pass, note index; loops unrolled lazily, pass by pass) and a min-heap of sounding notes; per block a single compare against `ticksToSamples(min over tracks of the next event)` decides whether any track has an event (idle block ≈ 21 ns for 1 track, 30 ns for 64; 0.47 ns/track). Events go to per-track lists in frame order, offs before ons at equal frames; event note ids are timeline-wide instance numbers. Chance / velocity range: `noteRandom(seed ^ playbackPass, note id, pass)`: the playback pass counts transport starts and arrangement loop wraps (T3.17-fix3, M3 review M16), so each playback and loop repeat decides anew, and a seed + command sequence (an offline render) decides the same way every time. A note's off is at least one sample after its on (L4). Wrap, locate and stop release every sounding note at that frame. Sequence swap: sounding notes follow their track id; ones still in the image (same id, start) keep sounding with the new length — a changed pitch (Hz, PitchSource, ratio, harmonic) is retuned by a Pitch step at frame 0 carrying the new identity (`kNoteEventRetune`, T2.6-fix3), never cut — removed ones get a note-off at frame 0 of the first new block; cursors re-seek at the current tick (no chasing).
- **Automation**: `AutomationRenderer` renders each lane into an audio-rate buffer per block (incremental cursor; fast paths for constant / straight / curved segments under a constant tempo; exact per-sample `samplesToTicks` when a breakpoint falls inside a run or the tempo ramps; an all-constant block costs O(1)); matches `evalAutomation(points, samplesToTicks(s))` (`pq/core/automation_curve.h`, Q39, header-only, shared with the views) within 6e-8 relative. While stopped it holds the value at the playhead. `writeAutomatedParams(params)` writes frame-0 values to `params[target]`; `automation().buffer(lane)` is the audio-rate buffer. **Audio-rate consumers (T2.6-fix2, M3 review M6)**: `AutomationLaneDesc::tap` (a `const float**` the consumer owns, e.g. a tuning table's `dsp::TuningLiveInputs`) gets the lane's buffer each block while it moves and null while the block is one constant (the consumer then reads the param, which holds it); the old image's taps are nulled at a swap and in the timeline's destructor. Lanes without a tap and with `perSample = false` render only their frame-0 value (one value per lane per block: the project link sets this for every lane but the tuning ones, whose consumers read params); the param values are bit-identical to the per-sample render's frame 0.
- **Integration**: `ImageRunner::setBlockHook`, `RenderRequest::hook`, `HostConfig::hook` take a `BlockHook` (`Timeline::blockHook()`: advance the timeline, write the snapshot and automated params) called before the event source each image block; `Timeline::eventSource(k)` is the `EventSource` of track k's VoiceEngine (T3.17 wires N instruments, one per slot). `process(sampleTime, frames)` is idempotent per engine block, so the hook and every track's source can all trigger it. Offline renders through it are deterministic and bit-identical to the same notes as a `NoteListSource` (tested).

### Leaf-atom kernel ABI (`pq/dsp/kernel.h`, `pq/dsp/atoms.h`; T1.6)
The interpreter's op record is `{KernelFn, KernelArgs}`; the JIT reproduces the same semantics inline.
- `using KernelFn = void (*)(const KernelArgs&) noexcept;` with `KernelArgs { const float* const* in; float* const* out; void* state; const void* resource; uint32_t frames; uint16_t numIn, numOut; uint32_t splMask; }`.
- **Lanes**: each kernel is compiled for L = 1 (global signal) or L = 8 (one voice group). A block buffer holds `frames · L` floats, frame-major with voices interleaved (`[s·8 + v]`, one frame = one `__m256`). Global stateless kernels are vectorised over time.
- **Rates**: an input is a block buffer (audio rate) or a Spl pattern of 8 floats constant over the block (param rate; per-voice values for L = 8, 8 copies of the value for L = 1). The Spl mask is a template specialisation chosen by `findKernel(atom, lanes, splMask)`, so unmodulated inputs cost one vector load per block and no per-sample branch.
- **Bools** are 32-bit lane masks (all ones / zero) in float slots, for both L. Every select on a bool (float `select`, integer `selecti`, the JIT's selects) reads the sign bit of the lane (blendvps), never single bytes, so a non-mask value at an engine input (1.0f: sign clear, false) means the same in every kernel and in both backends (T1b.1-fix1, M1 review L5).
- **State**: one POD block per stateful node (`atom_state.h`, 32-byte aligned, 8 lanes even for L = 1), sized by `stateBytes(atom, StateInit)` (`size_t`; a delay ring is at most `kMaxDelayRingBytes` = 1 GiB, i.e. `maxDelayFramesLimit(lanes)` frames, and `schedule()` rejects a larger `max` with a located error; each state arena is capped at 2 GiB) and written by `initState` (no allocation). Its type tag for hot swap is the `Atom` id (plus the lane count for delay lines, whose ring follows the header).
- **Resources** (wavetables, shaper curves, sample data, tuning tables) are immutable tables built off-thread (`tables.h`, `tuning_table.h`) and passed by pointer.
- **Tuning node** (T2.6, SPEC §3.3; `pq/dsp/tuning_table.h`, `pq/engine/tuning_signal.h`): `tuning_hz(degree, equave, hz, cents, generator, period, stretch, reference, table) → (hz, cents)`. The resource (`TuningTableView`, built by `engine::makeTuningTable(tuning)` from `tuning::linearTuningForm`; `Resources::tunings`, both backends) holds the EDO / MOS form per constant-order interval: pure cents = K·g − M·P, stretched by (1200 + stretch)/1200, Hz = reference · 2^(cents/1200), all in double (k·g − m·P reaches 10^4 ¢; float32 would cost ~1e-3 ¢) and rounded once. Per lane (K, M) stay cached until the generator leaves its interval (a region crossing, found at that sample) or the degree changes; with every tuning input a param the pitch is computed once per lane per block and the per-sample work is a blend. A lane without a degree, or whose `hz` input is 0 (before its onset), passes `hz` / `cents` through. Unmodulated param inputs equal to float32 of the definition's double value read the double (within an ulp of the static resolved pitch); when every tuning param input of a block is at its definition value the lane passes its own `hz` (the note's static Hz) through and computes only `cents` (T2.6-fix1: an unmodulated tuning node renders bit-identically to static pitches, and skips the exp2). **T2.6-fix2**: the table is a shared `dsp::TuningShape` (the interval table of a chain length: bounds, unrotated (k, m), the inverse map, and per boundary buildMOSScale's degenerate window 1e-6/q ¢ and hint-less nudge side; `engine::makeTuningShape(key)`) plus the tuning's definition (`dsp::TuningDefinition`: periods per equave, the mode as the root's chain position `rootChain`, the region hint, the values). Exact boundary generators take the side buildMOSScale's `chainSafeGenerator` nudges to (the region hint, else the side with fewer step sizes) and the 1e-7 ¢ nudge itself (H3); the mode is carried across intervals like the explorer's `transferModeRotation` (rotation in interval t = `inv[t][rootChain]`, `tuning::MosLinearTable::carryRotation`, shared with the piano roll's morph and `SetTuningParam`'s generator edit) (M7); `TuningTableView::live` (`dsp::TuningLiveInputs`, written each block by the timeline through `AutomationLaneDesc::tap`) replaces a param input by its automation buffer while the lane moves, so automation reaches the node per sample (M6). The kernel reads `KernelArgs::splMask` at run time (one function per lane count; the JIT calls it). **T2.6-fix3** (M3 review H4, H5, M9): two more inputs, `select` (voice.tuning) and `node`: with node ≥ 1 a lane is this node's only if select == node, and a selected lane without a degree is reference-relative (`hz · ref / ref₀`); a Degree lane's output is `ref · 2^(tc/1200) · E` with `E = hz / hz₀` (hz₀ = the degree's pitch at the table's definition; E = 1 within 4e-7, the note's own static Hz) — a Ratio anchored (through notes) to a Degree note carries the root's degree and sounds at its ratio to it, and a glide composes; `.cents` = the input cents + (tc − tc₀) + 1200·log2(ref/ref₀) (the engine's cents moved by the tuning; the reference term per block). Unmodulated (every param input at the definition) the node copies its inputs. A track patch binds it as `t = tuning_hz(voice.degree, voice.equave, voice.hz, voice.cents, gen, per, st, ref, table: k)`, `tv = tune_voices(t.hz, t.cents)` (see infer above): the instrument's voice.hz derives from the tuning signal. voice.degree / voice.equave are param-rate voice signals (VoiceSignal::Degree / Equave).
- **Silence declarations** (T1.x-silence): `dsp::silenceInfo(atom)` / `dsp::silenceTail(atom, init)`, see "Silence and sleep" under the ProgramImage ABI.
- **Registry ↔ kernel**: `pq/graph/kernel_map.h` (`kernelMapping(AtomId)`) is the one mapping from language atoms to kernels: the kernel, and per registry input whether it is a kernel input (durations: `· sr` inserted by `optimise()`, after which `TypedPatch::durationsInSamples` is set), a resource, or a state-init const (`seed`, `max` delay, z1 `init`). Atoms without a kernel are marked Structural (`channel`, `pack`), Constant (`sr`) or Engine (`voice.*`, `transport.*`, I/O, `voice_*` reducers). Registry `stateBytes` = the kernel's state block. Tested against both tables (QUESTIONS Q14).
- **Feedback**: `z1` and the delay lines also have split kernels (`z1:read`/`z1:write`, `delay*:read`/`delay:write`) sharing the atom's state, so a feedback SCC scheduled per sample can read at the start of the sample and write at the end.

### Widget toolkit (ui, T3.1: `pq/ui/widget.h`, `input.h`, `actions.h`, `test_driver.h`)
- **Tree**: `UiTree` owns one root `Widget`; widgets own their children (`add<W>(...)`). Ids are paths of names (`arrangement/track[3]/header/mute`; unnamed widgets are transparent). Override `paint`/`paintOver`, `onPointer`/`onKey`/`onText`, `onHoverChanged`/`onFocusChanged`/`onCaptureLost`, `onFrame`/`onTimer`, `contentExtent`, `arrange`.
- **Layout**: one top-down pass, no measure pass. `Length` = Fixed px | Flex weight, with min/max; containers are Row / Column / Stack / Custom (`Splitter`, `ScrollView`, views). Lengths are **logical px**; rects are **device px** = round(logical × `UiTree::uiScale()`), so text stays at integer pixel sizes. Only dirty subtrees are revisited.
- **HiDPI (`pq/ui/ui_scale.h`, T0.7-fix3)**: `UiScale` is the one logical → device conversion (`px`, `rect` snap each edge; `exact` for AA geometry; `fontPx(role) = round(role × scale)`). Source of truth: the app reads `SDL_GetWindowDisplayScale` at startup and on `SDL_EVENT_WINDOW_DISPLAY_SCALE_CHANGED` / `DISPLAY_CHANGED` (or `--scale`), then pushes it to `UiTree::setViewport` and `setSceneScale` (which re-resolves the `FontRole`s; new sizes are created there, never in paint); widgets read `PaintContext::scale` and `res.fonts`, scenes read `SceneTextures::scale`. Contract: layout and positions in logical px through `UiScale`; text through font roles (`TextSystem::font(FontRole, UiScale)`), never a hard-coded px size; the draw list, `lines.h` line widths, AA feathers and hairlines are device px and never read the scale; `TextSystem` measures and draws in device px. Pointer events are device px. `pqdaw --screenshot … --size WxH --scale S` renders W×H logical px at round(W·S)×round(H·S) device px.
- **Dense content** (clips, notes, grid) is drawn by one widget inside a `ScrollView`: it reports `contentExtent()` and paints only `PaintContext::clip`. Never one widget per note.
- **Redraw**: `markDirty()` adds the widget's clipped rect to the tree's `Damage`; layout adds the old and new rects of whatever moved. `requestFrame()` / `requestTimer()` are the only ways to animate; idle means no requests, and the loop blocks until the next event or `nextWakeTime()`. **Partial redraw (T0.7-fix1; per rect since T3.x-fix-paint)**: the frame loop reads the damage after layout (`UiTree::damageRects`), paints with `UiTree::paint(dl, res, now, span<const IRect> rects)` = one pass over the tree per damage rect under a draw-list clip of that rect (only widgets intersecting it paint; `PaintContext::clip` = the rect ∩ target, so virtualised views draw only that range; every pass of a frame shares `PaintContext::frame`, so per-frame stats and budgets count frames, not passes) and renders the list with those rects as the frame's damage. A playhead column, the control bar's readout and the header meters no longer repaint everything in their bounding box (M3 review H8). The single-region overload `paint(dl, res, now, region)` remains (benchmarks, tests). Contract for widgets and views: **paint only inside your rect** (push it as a clip if geometry could spill, e.g. glow, AA feathers past the edge; the text helpers `detail::drawText` / `views::paint::text` cut glyph ink themselves through `TextSystem::drawRunClipped`, horizontally to their box and vertically to `PaintContext::widget` = the painting widget's rect + declared overflow, with no extra draw command; `ui::Label` declares 4 px of bottom overflow for descenders) or declare the overflow with `setVisualOverflow(Insets)` (popup drop shadows do: damage and culling then use the grown rect), and report every visual change with `markDirty()` (or layout); anything drawn outside, or changed without damage, goes stale on screen.
- **Cancelling (T3.x-fix-edit)**: `UiTree::cancelInteraction()` = the captured widget's `onInteractionCancelled()` then `releaseCapture()` (`onCaptureLost`); `Shell::cancelInteraction()` (the app calls it on `SDL_EVENT_WINDOW_FOCUS_LOST`) adds cancelling any document gesture left open. Capture loss and Esc abandon drags in every editor (`Editor::abortDrag`, `ArrangementAutomation::abortDrag`, `RollState::abortDrag`); a range / rubber-band drag puts back the selection from before its press.
- **Input**: SDL-free `PointerEvent` / `KeyEvent` / `TextEvent` (`translateEvent` in `pq/ui/window.h` adapts SDL). A handled Down captures the pointer until every button is released; hover is frozen while captured. Keys go: focused widget → its ancestors (a focused text-entry widget swallows printable keys) → modal scopes (newest first; `ScopeRules` passthrough modifiers / swallow unbound, which is how macro mode works) → `keyScope`s of the focus chain → global → Tab traversal. `ActionRegistry` holds string ids → handler + enabled predicate; a `Keymap` is data (scope, chord → action id) and is resolved to indices in `UiTree::setKeymap`. Dispatch does not allocate.
- **Tests**: `TestDriver` builds a tree at a size and scale, injects events, runs a fake clock through update → paint, and renders through `OffscreenTarget`.

### Renderer, textures and glyph atlas (ui, T0.7 / T0.8; T0.8-fix1, T0.7-fix4: `pq/ui/renderer.h`, `atlas.h`, `text.h`)
- **Frame protocol** (Swapchain::endFrame, OffscreenTarget::submit): wait the slot's fence → `Renderer::upload(slot, layers)` → begin the command buffer → `recordTransfers(cb, slot)` → begin rendering → `record(cb, slot, frame)` → submit. Slots are used round-robin. Nothing in the renderer waits for the GPU (no `vkDeviceWaitIdle`, no `submitAndWait`); the slot fence wait is the only CPU–GPU sync.
- **Partial redraw (T0.7-fix1)**: a frame is a `FrameDesc` = ordered `DrawLayer`s + `full` or a list of disjoint whole-pixel damage rects (`Damage` keeps ≤ 8, merging overlapping/tiling ones) + the clear colour. Targets keep a persistent colour image (OffscreenTarget's own image; the Swapchain renders into its own persistent image and copies it whole into the acquired swapchain image, since swapchain images are not guaranteed to keep their contents). Full frames CLEAR; partial frames LOAD, `vkCmdClearAttachments` the rects and draw every command once per rect it reaches, scissored to clip ∩ rect, so each damaged pixel sees the clear then exactly the primitives covering it in list order: bit-identical to a full redraw (tested over 100 random sequences each for draw lists, a retained layer and a widget tree). A transient layer is copied into the slot's buffers each frame; a retained layer (`retained` id < 4, `version`) stays on the GPU per slot and is re-copied only when its version changes, and is indexed in runs of 64 triangles with vertex bounds so a partial frame draws only the runs reaching the damage. `Swapchain::preserved()` is false after a recreate (resize): the next frame must be full. The app draws in full when the damage covers > 50 % of the target, on resize/scale/theme changes and for scenes that cannot report damage.
- **Staging ring**: texture bytes are copied into persistently mapped 1 MiB chunks when they are handed over (`createTexture`, `updateTexture`, atlas dirty rects at `upload`), queued, bound to the next frame at `upload(slot)`, recorded as buffer → image copies between two batched barriers, and recycled when that slot comes round again. Overlapping copies to one texture in one frame are ordered (a covered copy is dropped, a partial overlap goes into a later batch behind a barrier).
- **Textures** (`TextureId`): `kAtlasTexture` (0) = the shared sprites (white texel, glow blob), valid on any atlas page; `atlasPageTexture(p)` (1..kMaxAtlasPages) = glyph page p; user textures from `kFirstUserTexture`. `createTexture` (async), `updateTexture(id, rect, rgba, rowPitch)` (async), `destroyTexture(id)` (deferred until every frame slot in flight at destroy time has been recycled; the id is then reused, so a draw list must not use a destroyed id). The draw list merges `kAtlasTexture` with any atlas page, so fills and labels stay one draw command.
- **Glyph atlas**: up to 4 pages of 1024² R8 coverage (each also holds the shared sprites), sampled through the view swizzle (1, 1, 1, R) so one pipeline/shader serves glyphs, sprites and RGBA images. Pages open on demand; when all are full the least recently used page not touched by the current frame is cleared (generation++); glyphs are re-rasterised on next use. If every page is in use this frame the glyph is dropped, counted (`Stats::atlasFull`) and reported once on stderr; its run is rebuilt on a later frame.
- **Tile atlas (T3.8-fix1, `pq/ui/tile_atlas.h`)**: cached raster tiles that a widget rasterises once on the CPU (off its paint path) and draws as one textured quad per frame instead of re-emitting the geometry. `Renderer::tiles()` owns one `TileAtlas` (also `SceneTextures::tiles`, `PaintResources::tiles`; null without a GPU, so CPU-only paints draw directly): up to `kMaxTilePages` = 4 R8 pages of 2048² (16 MiB GPU, the bound; no CPU copy of the pages), sampled like glyph pages through the (1, 1, 1, R) swizzle, so a coverage mask drawn with vertex colour c works for any colour. Page texture ids are the table's last four (`tilePageTexture(p)`; user ids end below them). `allocate(w, h)` = shelves (heights rounded to 4) with a transparent one-texel border all round; per-page LRU eviction by frame stamp, never a page touched in the current frame; a cleared page's generation goes up and its tiles read `!valid()`. `write(tile)` returns the zeroed texels (incl. border) queued for upload; `upload()` creates newly opened pages' images, stages the queue in one copy, then `clearUploads()` + `beginFrame()` (`TestDriver::step` calls `beginFrame()` only). A tile drawn 1:1 with uv on texel boundaries is texel-exact. Users: clip note previews (T3.8-fix1), automation envelopes (T3.x-fix-paint) and circuit symbol bodies (T4.2). **CPU coverage rasteriser (T4.2, `pq/ui/raster.h`)**: `rasterizeCoverage(dl, dst, w, h, pitch, origin)` renders untextured draw-list triangles into an R8 tile as the GPU would (pixel centres, vertex alpha interpolated, positions snapped to 1/256 px with exact integer edge functions and the top-left rule, coverage accumulated as alpha over), so a tile drawn in colour k equals the geometry drawn directly in k (tested to 1/255 at 1×/1.5×/2×).
- **Code editor** (T4.4, `pq/ui/code_editor.h`): a multi-line UTF-8 editor widget — caret / selection at code point boundaries, keyboard and mouse editing (docs/HOTKEYS.md), Enter keeps the indent, its own scrolling, line numbers, syntax colours through a `CodeHighlighter` (per line, with a carried state such as "inside a block comment"), `CodeMark`s (wavy underline, gutter marker, the message after the line). User edits change its text at once and are reported through `onEdit(offset, removed, inserted, typing)`; undo belongs to the owner (Ctrl+Z bubbles up), which applies changes back with `replace`. Paint shapes only the visible lines (one run per coloured token, through the text system's run cache); no caret blink (idle when focused).
- **Text frames**: `TextSystem::beginFrame()` once per frame (the app loop and `TestDriver` call it). A `TextRun` stays valid until the next `beginFrame()`/`clearRunCache()`: the run cache is trimmed only there (M8). `TextRun` carries per-cluster caret stops (`carets`, `caretX`, `hitTest`, LTR) and `shapeTruncated`/`drawTruncated` cut at a cluster boundary and append "…" (`truncated`, `visibleBytes`).

## 4. Data and file formats
- **Project**: a directory: `project.pqd` (JSON, UTF-8, `"schemaVersion"` first, currently 7 (3 = device chains (T4.1: every track's `"devices"`; 2 → 3 gives every MIDI track the default instrument with new ids); 4 = modulation wires (T4.7); 5 = user devices (T4.4-fix1: a device's own patch text, `"source"`); 6 = racks (T4.8: a device's `"rack"`); 7 = audio (T5.3: `"kind": "audio"` tracks, audio clips tagged `"kind": "audio"`, the top-level `"samples"` table; golden `tests/document/fixtures/audio/project.pqd`)) and ticks at PPQ 221,760, older files migrate on load (1 → 2 multiplies every tick by 8; `tools/fixtures/migrate_pqd_schema1.py` does the same to fixture text); layout in `pq/document/serialize.h` and the golden `tests/document/fixtures/full/project.pqd`: ticks and ids as integers, rationals as `"n/d"`, floating point as shortest round-trip numbers, embedded tuning definitions), `patches/*.pqp`, `samples/` (T5.8: samples are referenced where they are; Collect All and Save copies the used ones into `samples/imported/`), `cache/`.
- **JIT cache entries** (T1b.4, `src/jit/src/cache.cpp`): `<32 hex digits of the key>.pqjit` in the user cache or the AOT seed: a 64-byte header (magic `PQJITCCH`, format version, key, payload size, xxh3-128 of the payload), then the stage function names, the pointer-table description (host slots, kernel offsets into the executable), the IR hash (verify), statistics and the COFF object. Valid only for the executable that wrote it (its file hash is part of the key). Deletable at any time.
- **Patches**: `.pqp` text in the patch language ([PATCH_LANGUAGE.md](PATCH_LANGUAGE.md)). The visual layout is stored in the same file in a `layout { }` block (T4.3: keys for anonymous nodes, PATCH_LANGUAGE §2.2; written into hand-written files by `graph::spliceLayout`, which changes only that block).
- **Golden audio** for tests: 32-bit float mono/stereo WAV (`pq/media/wav_file.h` writes and reads them; `pq/engine/wav_file.h` forwards), 48 kHz, ≤ 1 MB each, in `tests/golden/audio/` from the patches in `tests/golden/patches/`, compared by `tests/golden/golden_audio.h` with a tolerance per test: absolute (max |Δ|, default 1e-4) AND spectral (Hann STFT of 4096, semitone bands from 20 Hz, dB re a full-scale sine floored at −80 dB, default 0.2 dB). Both backends must match the same goldens (T1.10; regeneration and pqc commands in `tools/README.md`).

## 5. Build configurations
- **Generator**: Ninja via `CMakePresets.json`. **Compiler**: MSVC v143 (cl.exe), x64. **Language**: C++20 (`/std:c++20`).
- **CRT**: match the prebuilt LLVM. All targets use the same `CMAKE_MSVC_RUNTIME_LIBRARY` (see `cmake/PqToolchain.cmake`). There is **no MSVC Debug configuration**, because the LLVM libs are release builds. The `dev` preset is `RelWithDebInfo` with optimisations reduced; `release` is fully optimised per translation unit (`/O2`, no `/GL` / `/LTCG`, so objects are cacheable and links fast: routine verification); `ship` is `release` plus whole-program optimisation (`/GL` + `/LTCG /OPT:REF /OPT:ICF`) for shipping builds and recorded benchmark numbers (Q91).
- **Flags**: `/W4 /permissive- /Zc:__cplusplus /utf-8 /arch:AVX2 /fp:precise`. Warnings are errors in our code (not third-party). SIMD kernels can be compiled with stricter or looser flags per file where measured.
- **CPU baseline check** (`pq/core/cpu_baseline.h`, T0.1-fix1): `/arch:AVX2` code may use the whole x86-64-v3 set (AVX, AVX2, FMA, BMI1/2, LZCNT, F16C, MOVBE). `pq_add_executable` links the OBJECT library `pq_cpu_check`: a CRT initialiser in `.CRT$XCB` that runs before every C++ static initialiser and `main`, and exits 1 with a message naming the missing features. It and the query it calls (`pq_cpu_baseline`, archived into `pq_core`) are C (no inline code shared with `/arch:AVX2` C++), compiled without `/arch:AVX2` and without `/GL` (`pq_target_baseline_defaults`). Test hook: `PQ_TEST_CPU_DISABLE=avx2[,fma,…]` forces features off in `pq_query_cpu_baseline()`, and so in `cpuFeatures()`.
- **Allocation trap** (`pq/core/alloc_trap.h`): the OBJECT library `pq_alloc_trap` replaces global `operator new/delete`. `pq_add_test` links it into every test executable (both presets), where an allocation or free inside an `RtScope` fails the running doctest case; use `pq::alloc_trap::countRtViolations([&]{ … })` to assert that an RT entry point does not allocate. `pq_add_executable` links it only when `PQ_ALLOC_TRAP_IN_APPS` is ON (default ON for dev, OFF for release), where a violation prints a stack trace and aborts. `malloc`/`free` and OS allocators are not interposable under `/MT` and are not caught.
- **Perf-labelled tests** (T0.x-flake): the default test run (`ctest --preset dev|release`, which `scripts/build.ps1` uses) must pass on a machine busy with other builds, so test assertions measure load-independent things: counts, deterministic or TSC-stamped timelines, the thread's own CPU time (`QueryThreadCycleTime`), and "eventually" waits of seconds. Wall-clock checks that need the scheduler to be on time live under the CTest label `perf`, which the test presets exclude: doctest cases tagged `* doctest::test_suite("perf")` in executables registered with `pq_add_test(<name> PERF …)` (they get a second entry `<name>_perf`; the default entry passes `--test-suite-exclude=perf`), and `pqdaw_window_selftest_perf` (the window self-test with `PQ_PERF_CHECKS=1`, which enforces the glyph-hitch interval and partial-redraw CPU-ratio criteria). Run them on a quiet machine with `./scripts/build.ps1 -Preset release -Perf` or `ctest --test-dir build/release -L perf`. A bare `ctest --test-dir build/<preset>` (no preset) runs both.
- **Compiler cache and test tiers** (T0.x-buildspeed): debug info is `/Z7` (embedded per object; dev only); C++20 module dependency scanning is off (`CMAKE_CXX_SCAN_FOR_MODULES`: pqdaw uses no named modules, and the scan is an extra uncached preprocessor run per TU). SYSTEM include directories are passed as plain `-I`, with third-party warnings silenced by `/external:anglebrackets /external:W0` (pqdaw's own headers are included with `"..."`, third-party ones with `<...>`): sccache hashes `-external:I<dir>` verbatim, which defeated sharing for every TU that sees a `_deps` include directory. Precompiled headers are disabled when the cache is in use (SDL3's PCH is not cacheable). When `scripts/get-sccache.ps1` has installed sccache it is the compiler launcher (`cmake/PqCompilerCache.cmake`), with one cache shared by every checkout and worktree; `scripts/build.ps1` sets it up. Since a cached object may come from another worktree, compiled code never contains a checkout's absolute paths: the path macros (`PQ_SOURCE_DIR`, `PQ_TEST_DATA_DIR`, `PQ_ASSETS_DIR`, `PQ_SOURCE_ASSETS_DIR`, `PQ_ALLOC_TRAP_PROBE`, `PQC_EXE`) name arrays defined in `pq_build_paths`, one generated TU compiled without the cache (`pq_use_build_paths`). `pq_add_test` registers each executable twice: the default entry excludes the doctest suite `slow`, and `<exe>_slow` (ctest label `slow`) runs only it; the test presets (so `build.ps1`) skip the `slow` and `perf` labels; `build.ps1 -Full` adds `slow`, while `perf` stays opt-in (`-Perf`).
- **Third-party code** comes in via `FetchContent` (through `pq_fetch_declare`, which shares verified archives between checkouts) as release archives pinned by SHA-256 (`URL_HASH`), so configuring needs no VCS, and is recorded in `docs/DEPENDENCIES.md`. All of it is linked statically (`BUILD_SHARED_LIBS` is forced OFF). Only permissive licences: MIT, BSD, zlib, Apache-2.0, Boost, MPL-2.0 (file-level), OFL for fonts. No GPL; LGPL only if dynamically linked and justified.

## 6. Conventions
- Files: `snake_case.h/.cpp`. Types: `PascalCase`. Functions and variables: `camelCase`. Constants: `kPascalCase`. Members: `trailingUnderscore_`.
- Headers: `#pragma once`; public headers in `src/<module>/include/pq/<module>/…`; private code in `src/<module>/src/…`.
- Errors: `pq::Result<T>` (value or `pq::Error{code, message, location}`) on non-RT paths. Exceptions are allowed only at the outermost non-RT boundaries (file I/O, parsing), and are caught there. Everything reachable from the audio thread is `noexcept`.
- No global mutable state except explicit singletons in `app/` (JIT compiler, audio device manager).
- Comments explain *why*. Every RT-path function says in its header comment that it is RT-safe.
