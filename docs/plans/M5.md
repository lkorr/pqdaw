# M5 plan (draft for user review)

Status: **draft 2026-10-30**, written by a planning agent from SPEC §7.2 (`sampleRead`, `clipPlayer`), §7.7, §9.1, §9.3, §9.4, §9.8, §12, §13 and §15 (2026-10-30: M5 re-scoped; Live parity in interaction details need not be exact), and from the code on `main` at d38a53b. Once approved, the tasks become `T5.n` in TASKS.md.

M5 = **audio tracks that samples can be dragged into** (audio clips with gain, transpose by resampling, reverse, fades and crossfades; warp Off and Re-Pitch only, the other warp modes stay in M6), **sample decoding + RT-safe disk streaming**, **waveform overviews**, **the browser** (places, background index, fuzzy search, tags, preview through a cue bus) and **the user library** (presets, racks, user devices, tunings, clips, default presets, hot-swap), **drag in and out** (browser and Explorer), and enough project sample management (copy into `samples/` on save, missing files, relink) that projects with samples are safe. Simpler and Drum Rack follow as M5b.

## Decisions taken in this plan (interaction details; SPEC §15 2026-10-30 says decide sensibly)

- **New module `media`** (`pq_media`, `pq::media`, depends on `core` + `dsp`): decoders, probes, the sample pool, stream rings (the RT read side is header-only, called by `engine`), waveform overviews. `engine` and `views` depend on it. **New module `library`** (`pq_library`, `pq::library`, depends on `media` + `document`): index, watcher, search, tags, user-library files. `views` depends on it. ARCHITECTURE §1 changes in T5.1 / T5.9.
- **Decoders**: dr_wav (WAV, RF64/W64, AIFF/AIFC), dr_flac, dr_mp3 (all from mackron/dr_libs, public domain or MIT-0) and stb_vorbis (OGG Vorbis; public domain or MIT). Single-header C, pinned to one commit archive by SHA-256, each compiled in its own TU with warnings silenced for that TU only. No libsndfile (LGPL), no miniaudio (larger than needed), no ffmpeg.
- **Resampler**: in-house polyphase windowed-sinc (Kaiser) in `dsp`, AVX2. No dependency: r8brain/libsamplerate don't fit a per-sample variable rate with our fixed-point positions.
- **Multi-file drops**: one new audio track per file (stems are the common case); **Ctrl** held = all files one after another on one track. Dropping onto a MIDI or group track inserts a new audio track after it. Dropping onto an audio track overwrites what lies under the new clip (Live's behaviour; it keeps the one-clip-at-a-time rule, Q41).
- **Reverse is non-destructive** (a clip flag, the player reads backwards), not a new `_R.wav` file as in Live.
- **Edge declick fades** (Live's "create fades on clip edges"): 2 ms at every clip start/end and loop wrap, not stored, a project setting (on by default). User fades longer than that replace them.
- **Clip gain** −∞ (−70) … +24 dB; **transpose** ±48 semitones expressed as cents, steps of the clip's tuning, or an exact ratio; detune ±50 ¢.
- **Library storage**: one JSON format per kind (`.pqpreset`, `.pqdevice`, `.pqtuning`, `.pqclip`), each written by the project serializer's own device/clip/tuning writers (one schema, one migration table). The **browser index** is an in-house binary file (columnar arrays + string pool + journal), not SQLite: it's a read-mostly table that we search in memory anyway, and loading flat arrays is faster than any query layer.
- **Tags survive renames**: tags and collections are keyed by the NTFS file ID (volume serial + 128-bit file ID) with path + size as the fallback.

## Proposed tasks (in dependency order; bundles of 1–3 per worker)

**T5.1 Audio file decoding: the `media` module** (`media` new, `cmake/PqDependencies.cmake`, `docs/DEPENDENCIES.md`, ARCHITECTURE §1; `engine/wav_file.h` moves to `media` with a forwarding header). Depends on: —.
Decoders as above behind one interface: `probe(path) → SampleInfo` (format, rate, channels, frames (exact; MP3 without a Xing/LAME header: scanned once and flagged), bit depth, acid/smpl-chunk BPM, root and loop points, a BPM parsed from the file name ("120bpm", "120 BPM"), NTFS file ID, size, mtime), header-only; `Decoder` (open, seek(frame), read(n) into planar float), non-RT; a fast `contentHash` (size + three 64 KiB windows; a full hash on collect for deduplication). MP3: gapless (LAME tag delay/padding), seek tables built once and kept. Declared sizes are capped by the file size, so a malicious header can't make the decoder allocate gigabytes.
- Accept: fixtures ≤ 64 KiB each in `tests/media/fixtures/`, generated by `tools/fixtures/make_audio_fixtures.*` from one known signal (sine sweep + impulses) with whatever encoder the machine has (ffmpeg / flac / lame / oggenc; provenance recorded; no encoder found = that format's fixture is a recorded blocker): WAV 16/24/32-int/32-float/extensible, RF64, AIFF 16/24, FLAC 16/24, MP3 CBR + VBR, OGG. Lossless formats are bit-exact against the generator's PCM. Lossy formats reach SNR ≥ 40 dB after the documented alignment (MP3 gapless: offset 0). 1000 random seeks return what a sequential decode returns (exact for every format with seek tables). Probe median ≤ 1 ms per file (warm OS cache). A malformed corpus (truncated, zero-length, absurd chunk sizes, random bytes) returns errors and never crashes or over-allocates; a `slow` mutation fuzz runs 10k cases per format. Decode throughput (MB/s per format) goes into RESULTS.
- CPU: probes read headers only. Decoders never run on the audio or UI thread. They decode straight into planar destination buffers; where a decoder only gives interleaved output, one AVX2 deinterleave pass.

**T5.2 Sample pool + RT-safe disk streaming** (`media`, `engine` read side, `app` owns the thread). Depends on: T5.1.
`SamplePool` (non-RT owner): one entry per distinct file (file ID + size + mtime), reference-counted by images, freed through the `EpochReclaimer`. Residency policy: decoded size ≤ 32 MiB per file (≈ 2.9 min stereo at 48 kHz) → **fully resident** (float32 planar with guard samples, like `SampleData`); larger → a **resident head** (2¹⁷ frames ≈ 2.7 s) plus streaming; a pool budget (preference, default 2 GiB) demotes the least recently used resident files to streamed. Long compressed files are decoded once into `cache/decoded/<hash>.f32` (the project cache; browser previews use `%LOCALAPPDATA%\pqdaw\decoded`, LRU-capped at 4 GiB), so streaming always does plain aligned reads.
Streams: a fixed pool of stream slots allocated at startup (256), each an SPSC ring of planar float frames (enough for 1 s at 4× speed) plus a request word. Audio-thread API (`noexcept`, RT-safe): `claim(sample, frame, direction)` (lock-free free-list, never blocks), `span(n)` (direct pointers into the ring, two spans at the wrap; missing frames read as silence and count an underrun), `release`. **The audio thread never signals a kernel object** (that would be a syscall): the disk thread waits on an event only the UI or the command path sets. While any stream is active it polls the request words every 2 ms, and with no active stream it blocks indefinitely. It runs at `THREAD_PRIORITY_ABOVE_NORMAL` and does 256 KiB overlapped reads with `FILE_FLAG_SEQUENTIAL_SCAN`, refilling a ring below half full. **Prefetch**: when the transport is stopped and the insert marker or loop start moves, the link asks the disk thread to fill streams for every clip crossing that tick, so Play starts with data ready. **Offline renders** use a blocking fill (the render thread waits), so renders are deterministic regardless of disk speed. Underruns feed the status bar's disk indicator (SPEC §9.8).
- Accept: RtScope tests on claim/span/release, including underrun and wrap. A two-thread stress test of 10⁶ random claim/read/release cycles checks the data against a direct decode. 64 concurrent stereo streams of 10-minute 48 kHz files at buffer 64, 2 min of NullDevice-paced realtime playback: 0 underruns (`perf` label, SSD; load recorded). A locate to a random mid-file point with prefetch has its data ready in ≤ 50 ms (indicative). An offline render of a streamed file is bit-identical to a fully resident render. Ring and head memory stay within the documented budget (asserted). With no active stream, the disk thread makes 0 wakeups in 10 s (counted).
- CPU: one acquire load per stream per block, no per-sample atomics, no copies on the audio thread (the player reads the ring in place); the disk thread is idle when nothing streams; small files never touch the streaming path.

**T5.3 Audio tracks + audio clips in the document** (`document`, schema 7; `views` only for the `Ctrl+T` binding; ARCHITECTURE "Document model", "Playback link"). Depends on: T5.1 (SampleInfo type only); can start in parallel with T5.2.
- `TrackKind::Audio` enabled. Its chain holds audio effects only; the mixer, sends, groups, solo and audibility work as for MIDI tracks. `Ctrl+T` = new audio track after the selection.
- A project **sample table**: `SampleRef { SampleId, path (project-relative `samples/…` or absolute), contentHash, frames, rate, channels, displayName }`. Many clips share one entry.
- `AudioClip { id, name, colour, start, length (ticks), sample, contentStartFrame (int64 source frames), warp ∈ {Off, RePitch} (M6 adds modes), sourceBpm (RePitch), loop (RePitch only, content ticks), gainDb, transpose (Cents | Steps of the clip's tuning, resolved at lowering so it follows retuning | Ratio n/d), detuneCents, reverse, fadeIn / fadeOut {length ticks, curve [−1, 1]}, crossfadeIn {length} (only with an adjacent left neighbour), active }`. **Warp Off clips keep their duration in time** (Q1): their arrangement length follows the tempo map from `start` and the played frames. The model stores the source frame span, and `clipEnd(project, clip)` derives the end tick.
- `ClipSlot` holds either a note clip or an audio clip (exactly one set). A shared `ClipSpan` accessor (start, end, active, colour, name) lets the generic edits (select, move, Alt-copy, split, Ctrl+D, delete, `0`, rename, colour, insert/delete/duplicate time, nudge, move to neighbour track) handle both. Audio clips may only sit on audio tracks, note clips only on MIDI tracks.
- Edits (one undo step each): create an audio track; add audio clip(s) (overwrite what lies under them); trim either edge (the audio stays at its absolute time: the left edge moves `contentStartFrame`); split; set gain / transpose / detune / reverse / warp / sourceBpm / fades / crossfade. A crossfade is dropped in the same command when its clips stop being adjacent.
- Serialization schema 7: `"samples"` table, `"kind": "audio"` tracks, audio clips tagged in the clips list. Migration 6 → 7 is a no-op. Strict-reader errors name the path (`$.tracks[2].clips[0].sample: unknown sample id 7`).
- Lowering: an audio track's patch = `clipPlayer(clip: <slot>)` (stereo; mono sources are duplicated) → device chain → the same mixer gains as a MIDI track. Per track an **audio sequence description** for the engine: clips with sample id, start sample law (Off: tempo map seconds; RePitch: content ticks ↔ source frames through sourceBpm), linear gain, fades, crossfade windows, reverse, resolved rate ratio. The project patch view's source node for an audio track becomes the clip player (no new editing).
- Accept: each edit is one undo step (scripted tests, including overwrite-on-drop and the crossfade drop rule). Split and trim keep the frame that plays at every absolute sample time unchanged, checked through the lowered descriptions. A tempo edit moves the end of an Off clip and leaves a RePitch clip's length in ticks unchanged. Time ops move and cut audio clips like note clips. Save → load is deep-equal on a fixture with every field. A schema-6 file loads unchanged. 10k audio clips save + load in ≤ 50 ms (release). The golden lowering text `audio-track.pqp` (via `doc::patchText`).
- CPU: gain, fades, transpose, reverse and crossfade edits change only the sequence image (runtime data, no recompile, like a note edit); only creating the track or editing its chain compiles its unit.

**T5.4 Clip player + resampler** (`dsp`, `engine`, `app` ProjectLink; ARCHITECTURE "Timeline", "Playback link"). Depends on: T5.2, T5.3.
- `dsp`: a polyphase windowed-sinc resampler, Kaiser, 64 taps × 256 phases with linear interpolation between phases (tables built once), AVX2 with 2 channels per pass, position as int64 frame + uint32 fraction (SPEC §3.1's fixed-point rule). **`rate == 1` with zero fraction is a straight copy.** For pitch-up (rate > 1) the cutoff scales by 1/rate: resident samples use 2×-decimated mip copies built at load (1 + ½ + ¼ … memory), and streamed samples use a kernel stretched by the rate (cost ∝ rate, recorded). A 16-tap "draft" quality is used only for browser scrubbing.
- `engine`: `clipPlayer` becomes a real engine source, replacing `Src::Silence`. Engine-owned per-track state survives hot swaps. The Timeline publishes an **AudioSequenceImage** per track by atomic swap, like `SequenceImage`. Each block: a cursor finds the clip(s) under [t, t+n) (at most 2: a crossfade). The source position at block start is computed **exactly** from ticks (Off: tempo map → seconds → source frames; RePitch: content ticks → frames through sourceBpm), so there is no drift. The rate is constant within a block (RePitch under a tempo ramp: linear over the block, re-anchored each block). The player reads resident data or a stream span, resamples, and applies gain × fade × declick envelope × crossfade gain in the same pass. Reverse reads backwards.
- **Sleep**: with no clip under the block and no fade tail left, the source reports silence, so the track's region sleeps (T1.x-silence). The idle cost is one compare per block.
- Accept:
  - **Placement and determinism**: sample-exact placement (warp Off, rate 1): an impulse at frame k of a clip at tick T sounds at sample(T) + k at 60 / 120 / 137.5 BPM and under tempo ramps, ±0 samples. RePitch is within ≤ 1 sample of the analytic integral after 10 min of a ramping tempo. Renders are bit-identical across device buffers 32/64/256/1024.
  - **Resampler quality**: passband ±0.1 dB to 20 kHz at 48 kHz. Images/aliases ≤ −80 dBFS for a full-scale sweep at transpose −24 … +24 st; the ±48 st extremes are measured and recorded.
  - **CPU** (ship, `bench_dsp` / `bench_render`): ≤ 15 ns per stereo frame resampling, ≤ 1 ns per frame for the rate-1 path. 64 audio tracks playing rate-1 clips ≤ 1 % of a core; 64 with transposed clips ≤ 6 %. 64 audio tracks with no clip under the playhead cost the same as 64 empty tracks (within noise).
  - **Safety and goldens**: RtScope on the player across clip boundaries, crossfades, loop wraps and underruns. Golden `audio-clips` (2 s: gain, fades, crossfade, reverse, ±7 st, RePitch at a tempo ramp). Also link `ship` `pq_bench_dsp` once (CLAUDE.md: kernel code).
- CPU: the copy path covers the common case (file rate = device rate, no transpose). Envelopes are fused into the resampler's output pass, with no extra buffer walks. Sleeping clip tracks cost nothing. The player never branches per sample on clip boundaries: the block is split at boundaries instead.

**T5.5 Waveform overviews** (`media`, `app` analysis worker, `ui` draw helper). Depends on: T5.1 (T5.2 for streamed reads).
- **Format**: per channel int16 min/max at 256 frames per bucket, plus ×4 mip levels up to the whole file (1 h stereo ≈ 7 MB).
- **Build**: one analysis worker at background priority (`THREAD_MODE_BACKGROUND_BEGIN`: low CPU and I/O priority) builds overviews progressively (published every 2²⁰ frames, so a long file fills in left → right).
- **Cache**: by content hash in `cache/waveforms/` (project samples) or `%LOCALAPPDATA%\pqdaw\waveforms\` (browser files; LRU 1 GiB).
- **Deep zoom** (< 256 frames per device px): drawn from the samples themselves (resident data, or a non-RT read cached per visible window).
- **Drawing**: `ui::drawWaveform(DrawList&, view, frame range, rect, gain, reverse, colour)` picks the coarsest level whose bucket ≤ frames per device px, reduces ≤ 4 buckets per column, and emits one triangle strip per channel (2 vertices per column); clip gain scales vertex y.
- Accept: a 10-min stereo 48 kHz WAV's overview builds in ≤ 250 ms (release, warm cache) and loads from the disk cache in ≤ 5 ms. Every level equals a brute-force min/max. Drawing a 2560-px clip takes ≤ 50 µs. Golden `waveform-lod` (one clip at 6 zooms, including sample level).
- CPU: built once per file ever (hash cache), never on the UI thread; draw cost is proportional to visible pixels, independent of file length.

**T5.6 Audio clips in the arrangement + the audio Clip View** 👁 (`views`, `ui`). Depends on: T5.3, T5.5 (T5.4 to hear it), T4.17.
- **Lanes**: lanes draw audio clips with the waveform (scaled by clip gain, mirrored when reversed), fade curves and handles, the crossfade X, badges for transpose / warp, and a red "missing" overlay. All generic clip editing applies.
- **Audio-specific editing**:
  - fade-in/out handles at the top corners (drag = length, Alt-drag = curve);
  - dragging a fade handle across an adjacent clip's edge makes a crossfade;
  - a clip-gain handle (top centre, vertical drag, Shift fine, double-click resets);
  - trimming stops at the file's ends (warp Off) or may extend through the loop (RePitch).
- **Clip View** (detail panel, audio clip): sample name / path / rate / bits; gain; transpose entry ("7" = 7 steps, "700c", "3/2"); detune; reverse; warp Off / Re-Pitch with a BPM field (seeded from tags, the file name, or the length as a whole number of bars); fades; the whole sample's waveform with the clip region; draggable start marker; the RePitch loop brace.
- Accept:
  - **Edits**: every gesture is one undo step (TestDriver); HOTKEYS and REVIEW are updated.
  - **Perf** (release, 2560×1440, 64 audio tracks × 200 clips with overviews loaded, 1× and 2× scale): full paint median ≤ 1.5 ms; scroll/zoom frame median ≤ 2 ms, p99 ≤ 4 ms; playhead frame ≤ 0.2 ms; memory flat over 10k scroll frames; idle 0 % CPU.
  - **Goldens**: `arrangement-audio` (fades, crossfade, gain, reverse, missing, mixed MIDI + audio tracks) and `clip-view-audio`.
- CPU: waveform geometry is cached per clip and zoom level and rebuilt only on change (like note previews); dense zoomed-out views go through the tile path.

**T5.7 Drag in: drag sessions + files from Explorer** (`ui`, `views`, `app`). Depends on: T5.3, T5.6.
- **`ui` drag sessions**: payload kinds Files / BrowserItems / Clips / Device, a ghost painter, and `dragOver(payload, pos) → feedback` / `drop` on target widgets, with auto-scroll near edges and Esc to cancel.
- **OS file drops**: SDL3's drop events (SDL 3.4 implements them on Windows through an OLE `IDropTarget`, with positions during the drag) are mapped to a Files payload, so Explorer drops and browser drops share one path. Check this first. If positions or hover feedback are missing, use our own `IDropTarget` via `RegisterDragDrop`.
- **Drop rules**: as in "Decisions" above. Ghost clips are drawn with their probed length while hovering. Dropped files start probing and loading heads on the first hover. A dropped folder is offered as a new browser Place. `.pqpreset` / `.pqdevice` dropped on a device chain → T5.11. MIDI files → status message (M11).
- Accept: simulated drops for every rule, each one undo step (n files = one step). Probing 100 dropped files and committing them as one undoable state takes ≤ 300 ms (probes run in parallel off the UI thread; overviews follow). A real Explorer drop is checked by hand (REVIEW). A resident sample plays at once when Play is pressed right after the drop.

**T5.8 Project samples: copy on save, collect all, missing files, relink** (`document`, `app`, `views`). Depends on: T5.3.
- **Save**: on save, every referenced sample outside the project directory is copied into `samples/imported/` (Q3; preference to turn it off). A name collision with the same hash reuses the file; a different hash gets a " (2)" suffix. Copies are incremental (skipped by hash) and run on a worker with progress in the status line. `project.pqd` is written last, after every copy is renamed into place. Updating a sample path is not an undo step. **File → Collect All and Save** also copies files that sit in library places.
- **Load**: a sample path resolves as project-relative → original absolute → search of the project folder, places and the last relink folder (name + size + hash).
- **Missing samples**: unresolved samples become *missing*: their clips are silent and drawn with the overlay, and the status line says "N samples missing — Relink…". Relink = pick a folder, recursive search by name with hash verification, applied to every match.
- **Cache**: `cache/` is never required (deletable; rebuilt).
- Accept: a project saved with external samples, then moved to another path, opens with every sample resolved. The collision rules are tested. A missing → relink round trip works. A fail point mid-copy leaves the old `project.pqd` intact (as `SaveFailPoint`). While 1 GB is copied, the UI's max frame stays ≤ 16 ms.

**T5.9 Browser index: places, indexer, watcher, search** (`library` new, ARCHITECTURE §1). Depends on: T5.1 (probe). Parallel with T5.2–T5.8.
- **Places and categories**: places are the User Library, the current project and added folders. Categories (virtual views over the index): Instruments, Audio Effects, Racks, Samples, Clips, Tunings, Patches/Subcircuits, and Grooves (empty until M10).
- **Indexer**: one thread at background priority walks the places and stores per file a record {dir id, name, type, size, mtime, file ID, probe fields, BPM/root hints}. Directory mtimes let it skip unchanged subtrees at startup. One overlapped recursive `ReadDirectoryChangesW` per place root (coalesced over 100 ms) keeps the index live; network and removable roots are rescanned on window focus.
- **Index file**: `%LOCALAPPDATA%\pqdaw\library\index.pqi`, written atomically at most every 5 s after changes, with a journal for crash safety.
- **Search** runs on a worker, and a new keystroke cancels the stale query. It is a fuzzy subsequence scorer (prefix, word starts, consecutive runs, a depth penalty) behind a 64-bit character-set prefilter per entry. Typing more characters narrows the previous result set. Filters: type, duration, BPM, rate, channels, tags/collections, place. The top 1000 results are materialised.
- **Tags**: 7 colour collections + free tags in `library/tags.json`, keyed by file ID.
- Accept:
  - **Index speed** (synthetic tree in a temp directory; 2k files in the default tier, 200k in `slow`): initial index time recorded (indicative); revalidating an unchanged 200k tree at startup ≤ 2 s; index load ≤ 150 ms.
  - **Watcher**: create / rename / delete / modify is reflected ≤ 500 ms later; at idle the indexer makes 0 wakeups (blocked on the change handles).
  - **Search**: median ≤ 5 ms per keystroke over 200k entries (release); results equal a brute-force reference scorer.
  - **Tags**: they survive a rename.
- CPU: the indexer reads headers only and never decodes; background priority keeps it out of the way of audio and UI; the prefilter rejects most entries with one AND.

**T5.10 Browser panel + preview through a cue bus** 👁 (`views`, `engine`, `app`). Depends on: T5.4, T5.5, T5.7, T5.9.
- **Panel** in `ShellSlot::Browser` (Ctrl+Alt+B):
  - search field (typing while the browser has focus goes to it);
  - sidebar (Collections, Categories, Places) and a virtualised content tree (columns: name, type, duration, BPM, rate; sortable), plus tag and filter chips;
  - a preview strip: waveform with scrub-on-click, preview on/off, volume, Raw / Sync (Re-Pitch to the project tempo when the BPM is known; tempo-synced *stretching* comes with M6).
- **Keys**: Up/Down select (auto-preview when on); Left/Right fold; Enter loads into the selection: a sample becomes a clip at the insert marker on the selected audio track (or a new one); a preset or device goes into the selected track's chain.
- **Context menu**: collections, Show in Explorer, rename/delete (user library only). Items drag out as T5.7 payloads.
- **`PreviewPlayer`** (engine): mixed after the project engine through `AudioOutput::setExtraSource`, to the main outputs or the cue output pair (new preference "Cue out"). ## Open questions as drafted (answered above)
1. **Unwarped (warp Off) clips when the tempo changes.** (a) They keep their duration in time: the audio is unchanged and the clip's length in beats follows the tempo (Live's behaviour). (b) They keep their length in ticks: audio gets cut or leaves a gap. **Recommend (a)**; it's what T5.3 specifies.
2. **Default warp for a newly dropped clip.** (a) Off: original speed and pitch. (b) Re-Pitch when a BPM is known: the clip follows the tempo but changes pitch. **Recommend (a) for M5**; M6 switches the default to auto-warp once Beats/Complex exist.
3. **Copying samples into `samples/` on save.** **Recommend copying every *used* file by default** (projects become self-contained, as you asked), with a preference to keep referencing files that sit in library places instead (avoids duplicating big sample packs). Collect All and Save always copies.
4. **User Library location.** **Recommend `Documents\pqdaw\User Library`**: visible, backed up with your documents, and changeable in Preferences. The alternative is `%APPDATA%\pqdaw`.
5. **When M5b runs.** **Recommend right after M5**: sample playback, streaming and the pool will exist, and Simpler only lacks the non-Re-Pitch warp modes, which can join in M6. The alternative is after M6.

## Risks
- **Two OLE roles in one window.** SDL3 registers its own drop target, and our drag source needs `OleInitialize` on the UI thread (STA). T5.7 opens with a spike that proves an Explorer drop and a drag-out both work in the real window before building on them.
- **Third-party decoder robustness** (stb_vorbis especially has had CVEs). Mitigations: pin the latest release, decode only off the RT and UI threads, cap allocations by file size, keep a malformed corpus plus a `slow` fuzz tier.
- **Lossy fixtures need an encoder on the machine.** If none exists, that format's fixture is a recorded blocker rather than a skipped test.
- **Streaming numbers depend on the disk and machine load.** The 64-stream test is in the `perf` label; network/removable places keep files resident or copy on drop (they never stream).
- **Disk use from caches** (decoded and waveform caches): both are content-hash keyed with LRU caps and deletable; the project `cache/` folder is never required.
- **Waveform paint budget at 64 × 200 clips.** The MIDI preview path needed tiles to meet 2 ms (T3.8-fix1); T5.6 starts from that path rather than a new one.
