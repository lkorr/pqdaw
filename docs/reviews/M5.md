## Summary verdict

**M5 is functionally broad and mostly sound, but it should not close before C1 and the High items are fixed.**

What is good:
- **The audio-thread design holds up under a skeptical read.**
  - The stream free list uses a tagged CAS (no ABA). The slot seqlock and the fill / consume protocol are ordered correctly.
  - Residency and mips are retired through the EpochReclaimer, and the player re-reads `view()` every block.
  - `rate == 1` is a true `gainCopy` (0.17 ns/frame). Idle tracks cost one compare (64 tracks × 200 clips idle: 53 ns per block).
- **The document is robust.** 509 fuzzed projects (field-targeted and random), each loaded and rendered: 0 crashes, 0 hangs, 0 NaN/Inf renders. Every out-of-range field was refused with a path-named error. Hot-swap keeps wires and mappings correctly. No use-after-free of the M4 H1 kind.
- **The numbers mostly meet the plan.**
  - Resampler 8.1 ns/stereo frame at rate ≤ 1, 10.6–11.4 at +1 st, mips hold pitch-up at 13.4–14.9 ns up to rate 16.
  - Search 2.7 ms per keystroke over 200k entries; index load 15.7 ms.
  - 10k audio clips save + load 47.9 ms; arrangement full paint 0.31 ms.
- **The whole suite passes in release with 0 warnings**, and the ship benches link.

What is wrong, in five clusters:
1. **One audio-thread use-after-free (C1).** The browser preview frees the image the audio thread is rendering whenever a new item is previewed during the first callback of the previous one. A probe crashed with a segfault in 2 of 3 runs. Auto-preview while walking the list with Up / Down is the ordinary trigger.
2. **Untrusted-input crashes and silent wrong audio in `media` (H1, H2).**
   - A malformed MP3, FLAC or Ogg header (or a corrupt `.pqwf`) makes the overview builder allocate terabytes. The `bad_alloc` escapes a detached thread and terminates the app. Selecting the file in the browser is enough.
   - The `.f32` decode cache is keyed by a sampled hash. Two files of the same size that differ outside the three 64 KiB windows share one cache entry, so the second file plays the first one's audio.
3. **Browser and view behaviour users hit at once (H3–H7).**
   - At sample-level zoom, a visible clip edge makes the arrangement decode and repaint forever.
   - Typing in the browser list also fires global shortcuts: Space starts the transport, B toggles Draw Mode.
   - Enter in the search field does nothing.
   - Every selection spawns a detached, normal-priority thread that decodes the whole file.
   - A tempo increase makes adjacent warp-Off clips overlap. They then play summed, and the crossfade is lost for good.
4. **Criteria that are not met on this commit, or not really tested.**
   - 2560-px waveform draw: 50.4–51.2 µs against ≤ 50 µs.
   - 64 audio tracks at rate 1: 1.02–1.04 % against ≤ 1 % of a core (indicative, under load).
   - Re-Pitch is not bit-identical across engine block sizes; the test covers warp Off only.
   - The T5.8 "1 GB copy, UI max frame ≤ 16 ms" test does not measure frames.
   - The disk thread's "idle costs nothing" fails after Stop (415 wakeups/s).

5. **Library and drag-and-drop robustness (H8, H9).**
   - The index snapshot's header counts sit outside its hash. One flipped bit makes the indexer allocate gigabytes and terminate the app. The bad file stays on disk, so this repeats on every launch.
   - Dragging a clip out of the window and back in imports the drag-out temp WAV, which pqdaw deletes at exit.
   - The payload checks themselves held: 80,000 fuzzed `index.pqi` / `index.pqj` / `tags.json` cases, 0 crashes.

**Counts:** 1 Critical, 9 High, 18 Medium, 21 Low.
- C1 and H1–H5, H7, H8 are verified by probes; H6 and H9 are code-read.
- Every fix is small or medium.

**Recommendation:** before closing M5, run one fix task for C1 and H1–H9, plus M1, M2, M14 and M15, which are cheap. Then re-run the affected tests, and repeat the 2560-px draw and audio/64 measurements on an idle machine.

## UI and aesthetic

I viewed every M5 golden at 1.0×: `arrangement-audio`, `clip-view-audio`, `waveform-lod` (ui), `browser-panel`, `browser-search`, `browser-hotswap`, `audio-prefs`, `audio-prefs-wasapi`. Contrast was computed (WCAG) from pixel colours sampled in the PNGs. I did not see 2.0×, hover states live, a real drag ghost, or the DISK indicator.

**What works.**
- **Audio clips read as Live's.** Dark waveform on the clip colour, title strip with name and right-aligned badges, the reversed / transposed clip and the crossfaded pair are understandable at a glance. Unselected waveform contrast is 4.0:1 on the clip colour, which is right for a body that should stay quiet.
- **`waveform-lod` is solid.** The level switch is invisible across 5000 → 0.3 frames per px; the sample-level rows draw a clean line between samples; reverse and +4 dB read correctly.
- **The browser's structure is right:** sidebar of Collections / Categories / Places, a sortable content list, a preview strip, hot-swap as a banner mode. Density matches the rest of the app.
- **The Clip View's sample display** shows the clip region on the full sample, with the outside darkened and the loop brace on top: the right model.

**Ranked changes** (most user impact first):
1. **Make "Missing" readable and unmistakable.** The red "Missing" badge on the grey title strip is **1.39:1** (sampled: `#F06A62` on `#B0B0B0`), essentially invisible, and the body is a flat salmon `#A45956` with no waveform. In `browser-panel.png` the clip is too narrow for the badge, so a missing clip there is just a pink block. Use Live's approach: a dark body with diagonal hatching, the title strip kept in the track colour, and white "Offline" text (or a broken-link glyph that fits at any width). Show the missing file name in the status line on hover.
2. **The Clip View needs a layout pass.**
   - The left 210 px of the detail panel is an empty column.
   - The properties are a single label/value form running down the panel; Live groups them into Sample (name, rate, warp, BPM) and Clip (gain, transpose, detune, reverse, fades) boxes side by side, which halves the height and puts gain and transpose next to each other.
   - The sample display has no time ruler, no zoom and no amplitude reference. At +6 dB clip gain the waveform is scaled into the edges of the box, so peaks flatten and the display suggests clipping that isn't there. Draw the display at unity and show gain as a line or a numeric overlay.
   - The start marker is a 1-px white line at the region's left edge, indistinguishable from the region border. Use a flag at the top like the loop brace's end caps.
   - Greying is inconsistent: Transpose is greyed for Re-Pitch (Q145.2), Detune is not, though both are ignored.
3. **Fades and the crossfade X are too heavy and too white.** The fade curves and the X are opaque white 1–2 px lines over the waveform, and on the selected clip (whose body lightens to `#B89056`, waveform contrast falling to 3.0:1) the fade wash is hard to see. Draw the curves in a darker shade of the clip colour (or black at 60 %), shade the faded area as a translucent darkening, and draw the X only on hover / selection; keep the selected body at the normal colour and mark selection with the title strip and an outline, as Live does.
4. **Badges and the track headers.** "RP 100" is cryptic; "Re-Pitch · 100 BPM" fits, or a warp glyph + "100". Audio and MIDI track headers are indistinguishable (Drums / Vox / Lost vs Keys differ only by Keys' tuning chip); add a small waveform / note glyph to the header or the track name field. Re-Pitch loop seams in the Vox clip restart the waveform with no mark (REVIEW "Known gaps"); a 1-px darker seam line at each wrap would make the loop legible.
5. **Browser chrome is noisy.**
   - The row of seven unlabelled colour squares under the search field duplicates the Collections section right below it, and the permanent "Dur: Any · BPM: Any · Rate: Any · Ch: Any" chip row costs a line for filters that are off. Collapse both into one "Filter" button that expands, and show chips only when set.
   - The Type column repeats the file extension that the name already shows; in hot-swap the names still show ".pqpreset" and the Dur / BPM / Rate columns are empty. Hide extensions for library files and hide columns that are empty for the current view.
   - Search results don't highlight the matched characters and don't show where a result lives; Live shows the folder on selection. Bold the matched runs (the scorer already knows them) and show the parent folder dimmed in the row or the info line.
   - Section headers ("COLLECTIONS", "CATEGORIES", "PLACES") are low-contrast grey caps; one step lighter and a 4 px gap above each would group the sidebar better.
6. **Preview strip.** The light-grey waveform on near-black is the only waveform in the app that isn't dark-on-colour; there is no play position, so a click-to-scrub has no feedback until the next click. "Prev" as a text toggle reads like "Previous"; use a headphone glyph (Live) or "Preview". In hot-swap mode the strip says "Select a sample to preview it" under a preset list; hide the strip in that mode.
7. **Hot-swap banner.** It names the device ("presets of Operator") but the device in the Device view isn't marked as the target, and the sidebar keeps "User Library" selected, which contradicts the filtered list. Highlight the target device's title bar while hot-swap is on, and deselect the sidebar.
8. **Preferences.** The new "Cue Out" row is placed well. But the window still has one page ("Audio"); the library location, cache sizes, pool budget and drag-out bit depth have nowhere to go (M13). The modal also has no dimmed backdrop, so it reads as part of the arrangement.
9. **`waveform-lod`, minor.** Stereo channels butt together with no separator or centre line; a 1-px darker separator between L and R and a faint zero line at sample-level zoom would help reading, as in Live.
