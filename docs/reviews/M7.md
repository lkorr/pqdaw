Reviewer: independent M7 review agent (T7.10), 2026-11-14, `main` at `34ec2837` (branch `task/T7.10-review`).

## What I did

- **Four parallel deep reads** (engine; document; app lowering + its tests; piano-roll views), each by a sub-reviewer with a
  checklist, then I re-read the load-bearing lines of every High finding and of M1–M3 myself.
- **Looked at all 12 M7 goldens** and the five inspiration screenshots + the chat log.
- **Nothing was built or run.** Memory was tight and a `-Full` run was in progress; every finding below is from reading

## Summary verdict

**The engine side is solid; the document and roll have holes around clip edits and around gestures that recognise or
change data silently. M7 should not close before H1–H5.**

What is good:
- **Realtime design.** Curve work is per breakpoint, ramps end by assigning the target (no drift), note-offs are never
  dropped, chase is a max-end tree (not a scan), Sync is bounded by the compaction budget, no-curve tracks run the old
  path. No allocation, lock or unbounded loop found on the audio thread. Sequence build rejects NaN / oversize curves
  with an error, not truncation.
- **Exactness at holds.** `jiVoiceRatio` is overflow-checked rational arithmetic, the pinned voice is exact, `walkJiTerm`
  keeps the pin's rational identity, `lcmCapped` refuses instead of overflowing, `clipHarmonics` is a capped lcm (no
  search). Parallel voices get identical breakpoints, so the 1 ¢ tolerance (Q282) does not detune pure intervals.
- **Validation / serialization** of the new model is thorough; no out-of-bounds path from a hand-edited file; no
  compatibility shims; no "Subharmonic" remains; no TODOs or stubs.
- **Roll tests use real dispatch** for every gesture (menus included); the proportion and harmonic fields reject bad
  input with a message; previews do not write the document per mouse move.

What is wrong, in five clusters:
1. **JI data vs clip edits (H1, H2, H3, M2).** A sounding object that begins before its clip's start marker is silent
   (trim a clip's left edge, split a clip through an object). Copying a clip silences every note drawn under "Is
   Harmonic N". Deleting or splitting away the anchor note silences its dependants. Split + consolidate doubles an
   object's head.
2. **Gestures that change data silently (H4, H5, M7–M10).** A free-drawn curve is mistaken for a "bend out" and jumps
   when the note is resized; a Shift + click with a 4 px slip turns the whole selection into Cents notes.
3. **Consumers that do not know M7 (M3, M4, M5).** MIDI export, arrangement thumbnails, a Ratio note anchored to a
   tuned / bent note.
4. **CPU (M12–M14).** Every committed note edit re-flattens every object of the track; `SetNoteCurve` copies the whole
   curve list per command; inner notes are re-evaluated per paint.
5. **Tests (M15).** Three bounds were set far from the plan's acceptance lines, one loosened to pass.

**Counts: 0 Critical, 5 High, 19 Medium, 20 Low.**

## High

### H1 · A sounding JI object that starts before the clip's start marker never plays — CONFIRMED
`src/app/src/project_link_ji.cpp:283` (`nd.start = o.start;`), with `src/engine/include/pq/engine/sequence.h:13` ("Notes
that can never play (before the start marker …) are dropped at build time") and `src/document/src/edit_common.cpp:171-177`.
- **Scenario A:** drag a clip's left edge a sixteenth into an 8-bar object. The whole chord is silent for 8 bars; the
  roll still draws the box. Chase cannot help: the notes are not in the image.
- **Scenario B:** split a clip through an object (the ordinary way to cut a morph in two). The right half gets a copy
  of the object (fresh ids) that starts before `right.contentStart`: drawn, permanently silent. Linear playback goes
  quiet at the cut.
- Same for each loop pass when the loop start cuts an object (pass 0 plays it, later passes do not).
- **Fix:** in `ClipJiLowering::voices`, start each voice note at `max(o.start, pass content start)` with Hz / ratio /
  harmonic / unison taken there (`jiVoiceHz(o, t, v, at)`); curves are in content ticks and need no change. Or head-cut
  the object in the document when the clip is split / trimmed (shares code with M2's fix).
- **Test:** `test_ji_playback.cpp` Rig: `create(0, 8*kQ, {4,5,6})`, clip `contentStart = kQ`, build, `REQUIRE(notes == 3)`.

### H2 · Copying a clip silences every note drawn under "Is Harmonic N" — CONFIRMED
`src/document/src/edit_common.cpp:238-268` (`cloneClip`): every note gets `m.id = ids.note()`, only JI-object references
are remapped (`remapJiPitch`); `AnchorKind::Note` anchor ids and `ClipFundamental::{anchor, steps}` (copied by
`withNotes`) still name the source clip's note ids.
- T7.5b made Note-anchored Ratio notes the identity of everything drawn after "Is Harmonic N"
  (`src/views/src/piano_roll/roll_state.cpp:432`).
- **Scenario:** declare a note harmonic 4, draw a melody, Ctrl+D the clip (or Alt-drag copy, `arrangement/editing.cpp:114`,
  or split it while looped, `edit_common.cpp:143`). In the copy the melody does not resolve and the lowering drops it
  (`src/app/src/project_link.cpp:224`: `if (!np.hz) continue;`); the declared harmonic is gone too.
- **Fix:** build an old → new NoteId map in `cloneClip`; remap Note anchors, `fundamental.anchor.note`,
  `fundamental.steps[].note`.
- **Test:** note A (Degree), B = Ratio 3/2 anchored to A, `lockFundamental(A, 4)`, `duplicateClips`; the copy's B has
  `hz` and `clipHarmonics(copy)` has an anchor.

### H3 · Deleting the anchor note, or splitting it away, silences every note anchored to it — CONFIRMED
`src/document/src/edit_notes.cpp:303-313` (`deleteNotes` is a bare `RemoveNotes`); `src/document/src/edit_common.cpp:150-158`
(a non-looped split moves notes by start only); also `edit_ji.cpp:225` (`replaceNotes`) and `:407`
(`deleteJiObject(withNotes)`).
- **Scenario:** "Is Harmonic 5" on a note, draw ten notes, delete the first note (it was only a reference): ten silent
  notes, still drawn. Or: anchor in bar 1, melody in bars 2–4, split at bar 2: the right clip is silent.
- **Fix:** in those builders bake the dependants in the same batch (exact reference Ratio when the anchor is one, else
  Cents), as `deleteJiObject(withNotes = false)` already does for inner notes; for a split, bake or copy the anchor as a
  disabled note. Decide which and say so in the status line.

### H4 · A free-drawn pitch curve is taken for a "Bend Out": resizing the note moves the drawing — CONFIRMED
`src/views/src/piano_roll/roll_pen.cpp:85-90` (`leadOutBegin`: any curve whose last value ≠ 0 has a lead-out starting at
its last zero; the curve's end is never compared with the note's end), used by `retimeCurve` `:560`, `withBend` `:138`,
`:470`, `:710`.
- A pen stroke always starts on an exact 0 and holds a non-zero end, so it always matches.
- **Scenario:** draw a ramp over the first quarter of a long note, then lengthen the note by a grid step: the ramp jumps
  to the note's end. What plays changes; nothing says so.
- The note's menu shows "Bend Out ▸ S-Curve ✓"; choosing "Straight" replaces the drawing with a ramp at the end. Alt +
  right edge erases the stroke; Add Vibrato skips its span.
- **Fix:** a lead-out must end at the note's length (pass the length into `leadOutBegin` / `bendLength` /
  `retimeCurve`); the better end state is Q289 (b): store bends as bends, not as recognised shapes.
- **Test:** real-dispatch: pen stroke, then resize; the stroke's ticks are unchanged.

### H5 · Shift + click with a few pixels of slip turns the whole selection into Cents notes — CONFIRMED
`src/views/src/piano_roll/roll_input.cpp:296-300` (`d.cents = centsAtScreenY(p.y) - centsAtScreenY(d.press.y)`),
`roll_state.cpp:1560` (`if (d.cents != 0.0) apply(detuneEdit…)`), `roll_pen.cpp:620-645`. No vertical dead zone beyond the
3 px click slop.
- **Scenario:** 20 Degree / Ratio notes selected, Shift + click a 21st to add it, the hand moves 4 px: all 21 become
  `PitchId::fromCents`, ~29 ¢ off. They no longer follow the tuning, exact ratios are gone, notes anchored to them
  shift. On screen a Cents note within half a row sits on the same row; no status text. Also any Shift + horizontal
  drag (a constrained move in most editors) detunes by whatever the hand wobbled.
- This breaks "pitch identities stay exact" by accident, in the gesture users already use to extend a selection.
- **Fix:** a dead zone (about half a row) before the detune engages; a status line ("Detuned +29 ¢ · 21 notes are now
  Cents"); better: keep the identity and store the offset as a constant pitch curve, so "Clear Bends" restores it.

## Medium

### M1 · The 256-event cap drops chased voices of a large object on every loop wrap — SUSPECTED (arithmetic read, not run)
`src/engine/src/timeline.cpp:688` (`eventCount_ + 2 + heapSize > maxEventsPerTrack` → `droppedNoteOns`), `:999`;
`src/app/src/project_link.cpp:51` (`kTimelineEventsPerTrack = 256`, 128 sounding).
- The chase runs in the block that also holds the old notes' offs. With N offs and 3 events per chased curved voice
  (on + pitch ramp + gain ramp), voice i is dropped once N + 4·i + 2 > 256.
- **Scenario:** an arrangement loop inside a sustained 64-voice object mid-glide: voices 48–63 are silent after every
  wrap until the object ends. Plain notes: above ~85 sustained across a wrap. A `covering()` result truncated at the
  scratch size is not counted at all. A dropped last ramp of a curve leaves the note on the wrong pitch to its end
  (`:783-791`).
- Two overlapping 64-voice objects also exceed the 128 sounding limit (earliest-ending note cut).
- **Fix:** cap ≥ 6 × maxSounding (1024 is what the voice side already takes), or carry unfitted chased ons into the next
  block. **Test:** 64 curved notes across a loop start; `droppedNoteOns == 0` after a wrap.

### M2 · Split then consolidate doubles a sounding object's head — CONFIRMED (placement); the test asserts it
`src/document/src/edit_clips.cpp:376-381`: an object that starts before a segment's `contentFrom` is cut at its tail
only; `tests/document/test_ji.cpp:919` checks `o.start == kBar - kPpq` for both copies.
- **Scenario:** split a clip through an object, consolidate: the merged clip holds the left copy (cut at the bar) and
  the right copy at its original start and full length; both sound over the head (louder, phasey).
- **Fix:** head-cut in `takeObject` (factor out `resizeJiObject`'s Start-edge code), or re-merge copies of one object in
  adjacent segments. Fix the test's expectation with it.

### M3 · MIDI export silently drops sounding objects and every curve — CONFIRMED
`src/document/src/midi_export.cpp:136-179` iterates `c.notes` only; no reference to `ji` or `curves`.
- **Scenario:** export a clip made of drawn JI boxes: an empty track, nothing in the report. A Tune-to-JI chord exports
  at its start pitches without the glide; bends and vibrato are lost. `midi_export.h:26` still says Harmonic is skipped.
- **Fix:** at minimum report counters (`objectsSkipped`, `curvesDropped`) shown to the user; properly: object voices and
  curves as per-note pitch bend.

### M4 · Arrangement clip thumbnails ignore M7 data — CONFIRMED (code and goldens)
`src/views/src/arrangement/model.cpp:74-80` (Harmonic → falls to the reference pitch), `:116`, `lanes.cpp:336,792`
(`notes.empty()`).
- Visible in `pianoroll-ji-morph.png`, `-ji-undertone.png`, `-ride.png`: the clip in the arrangement is blank and the
  panel says "Notes 0" although it plays a 7-voice chord. After Tune to JI the tuned notes collapse onto one row.
- **Fix:** preview from `resolveClipPitches` plus one bar per object voice (stop-0 pitch is enough).

### M5 · A Ratio note anchored to a tuned or bent note follows neither the tuning glide nor the bend — CONFIRMED
`src/document/src/pitch_resolve.cpp:91-96` uses the anchor's pitch at the anchor's own start.
- **Scenario (the user's two features together):** Tune-to-JI a 12-EDO triad (E glides −14 ¢ to 5/4), then draw a 3/2
  above the E under "Is Harmonic": the new note is 3/2 above the old 12-EDO E for its whole length, 14 ¢ sharp of pure —
  even when it starts after the glide has finished.
- **Fix:** resolve the anchor at the dependant's start (anchor Hz × its curve there). Whether the dependant should also
  follow a bend during its span is a design question (QUESTIONS).

### M6 · "Tune to JI" re-approximates notes that are already exact JI — path CONFIRMED, cents SUSPECTED
`src/document/src/edit_ji.cpp:159-182`: the exact branch needs both notes Reference-anchored; Note-anchored ratios (all
"Is Harmonic" notes), Harmonic and JiFundamental notes go through `simplestRatioNear` with up to ±20 ¢ tolerance, and the
fundamental becomes `fromCents`.
- **Scenario:** two notes exactly 16/15 apart under an anchor, Tune to JI: a simpler neighbour (15/14, 14/13) may be
  chosen: 8–17 ¢ off, identity lost.
- **Fix:** exact ratio whenever both notes reach a common root by rationals; cents only for tempered pairs.
  **Test:** `jiFromNotes` on Ratio 1/1 and 16/15 anchored to A → terms `{15, 16}`.

### M7 · Draw Mode: a click that wanders > 3 px no longer erases, and can leave a detuned tail — CONFIRMED
`src/views/src/piano_roll/roll_input.cpp:497, :576`; `roll_pen.cpp` `penTo`.
- Before T7.6 the press deleted. Now a slightly moved click becomes a pen stroke: the note stays, and with a vertical
  slip the rest of it is held 20–30 ¢ off. No drag-erase across notes any more.
- **Fix:** a minimum stroke (~8 px) before a curve is stored; consider erase on right-drag or Ctrl.

### M8 · Draw Mode: a drag starting on an object's lowest voice draws a ride curve instead of notes — CONFIRMED
`roll_input.cpp:256-266`, `roll_pen.cpp:369`. Voice 0 lies on the box's bottom row: starting a run of notes there bends
every voice of the object by the hand's wobble and adds no note. **Fix:** ride pen only on a selected object (or with
a modifier).

### M9 · "Previous / next note" for a bend is the nearest in time anywhere in the clip — CONFIRMED
`roll_pen.cpp:403-425`: pitch only breaks exact ties.
- **Scenario:** a melody note whose predecessor ends 10 ticks early while a bass note ends exactly on the edge: Alt +
  left edge scoops in from the bass two octaves below. Same pitch neighbour: the gesture does nothing, no message.
- **Fix:** among notes ending within a grid step, the nearest in pitch; status line for "nothing to bend from".

### M10 · A double-click on empty space inside any object's box enters the object instead of adding a note — CONFIRMED
`roll_input.cpp:505-517`. Tune to JI wraps ordinary chords in boxes; adding a plain note between them by double-click
enters the object, and the next double-click adds a Harmonic voice note. **Fix:** enter from the header / border / a
voice line only.

### M11 · No mouse path to the JI tool or the walk; `J`, `T` and the digit stop entry are dead with the computer keyboard on — CONFIRMED
`src/views/src/piano_roll/clip_view.cpp:68` (only `J`), empty-space menu `roll_input.cpp:811` has no entry; no "Walk Up /
Down" on a harmonic number; `ui_tree.cpp:666` gives the key listener J / T / 1–9 first (HOTKEYS documents J and T, not
the digits). The user asked for "mouse and keyboard": the entry point of the feature has no visible control.
**Fix:** a JI tool button beside Fold / Scale and a menu entry; Walk entries in the object menu.

### M12 · CPU: every committed note edit re-flattens every object of the track; descs deep-copied per publish — CONFIRMED
`src/app/src/project_link.cpp:947` (cache key = the track pointer), `:957` (`descs[slot] = e.desc;`).
- `NoteClip::ji` is shared across note edits, yet one note move re-runs `jiVoicePlan` for all objects: 3.7 ms per
  100 × 8 × 32 (PROGRESS), on the UI thread, per commit. Since T7.1 a `NoteDesc` owns two vectors, so the per-publish
  copy is up to two allocations per curved note for all tracks, cache hits included.
- **Fix:** cache lowered voices per clip keyed on `(ji.get(), tuning, timeline, start, contentStart)`; hand `build` the
  descs by pointer. Smaller: `noteCurve` computes a full plan for notes that need only the spacing; scaffold plans
  compute gains nobody reads.

### M13 · CPU: `SetNoteCurve` copies the clip's whole curve list per command — CONFIRMED
`src/document/src/apply.cpp:1423`; builders emit one command per note (`edit_notes.cpp:522-525`, `:292`,
`edit_ji.cpp:324`) with linear curve lookups (`edit_notes.cpp:289`, `edit_ji.cpp:304`).
- **Scenario:** Ctrl+D on 2000 vibrato notes ≈ 2000 full list copies + clip rebuilds: a visible hitch.
- **Fix:** one `SetNoteCurves{clip, vector}` command, or curves carried by `AddNotes`.

### M14 · CPU: notes that follow a voice are re-evaluated uncached on every paint; the 2 ms claim is not in the default tier — CONFIRMED (structure)
`src/views/src/piano_roll/roll_ji.cpp:959-985` (`pathCents` every 2 px per note: `findJiObject` + `jiVoiceCents`), culled
by time only. `tests/views/test_piano_roll_ji.cpp:502` has no inner / curved notes and is labelled `perf`.
**Fix:** walk the cached `JiView` plan as `voicePath` does; cull by y; add inner notes to the perf case.

### M15 · Tests: bounds far from the plan's acceptance, one loosened to pass (rule 4) — CONFIRMED
- `tests/document/test_ji.cpp:234`: `worst <= (ride ? 0.05 : 0.0505)`, changed from 0.05 in 568c09a9 because the new
  variant measured 0.0502. Cause: `src/document/src/ji_object.cpp:331` rounds marched breakpoints to ticks after sizing
  the step for exactly the tolerance; for very short glides the excess is not bounded by 1 %. Inaudible, but the code
  should be fixed (size the step with the rounding margin) and the bound restored.
- `tests/app/test_ji_playback.cpp:316-317`: `late > -1.5`, `early > -6.0` dB in 10 ms windows; the plan says −0.5 dB,
  Q281 measured −0.25 / −0.13. The plan line was never amended. Set −0.5 or amend the plan with the user.
- `:805`: lowering `best < 25.0` ms against a 5 ms target (3.7 measured): cannot catch a 4× regression.
- The three rewritten `test_timeline.cpp` chase cases are legitimate (they asserted no-chase; Q278 changed it).
- No test at all: clip `start` / `contentStart` ≠ 0 or looped clips with objects (would have caught H1), `tempoMoves`,
  a refused Sync at app level, any instrument other than a sine through a Sync at app level, T7.6 gestures in a MOS /
  equidistant roll, Esc mid-drag for pen / bend / detune / stop gestures, resize of a free-drawn note (H4).

### M16 · `voice.harmonic` / `voice.ratio` are stop-0 values for an object's whole life — CONFIRMED
`src/app/src/project_link_ji.cpp:288-289`; plan decision 4 says "exact at holds". In 4:5:6 → 2:3 → 1 a patch reading
`voice.harmonic` still sees 4 / 5 / 6. **Fix:** carry the identity on the arrival's Pitch event (the retune path has
it), or record the limit in QUESTIONS.

### M17 · UX: "switch a chord between the tuning and JI" is one action in, but not a switch — CONFIRMED (code + goldens)
- In: select, `Ctrl+Shift+J` — good, and the result is legible (`12-EDO → 4:5:6`, `−14¢` on the voice).
- Back: point inside the object and press `T` (adds a tuning stop there) or the object's menu "Remove JI Tuning". There
  is no toggle on the same key, and the two "back"s mean different things.
- The proportion is each voice's nearest simple ratio to the lowest: C–E–G–B♭ gives `20:25:30:36`
  (`pianoroll-tune-to-ji.png`), where most users expect 4:5:6:7. The only way to change it is to double-click the stop
  label and retype. **Fix:** `Ctrl+Shift+J` on notes already tuned removes the tuning (a real toggle); offer the 2–3
  best proportions (lowest terms first) in the status / a small menu after tuning.

### M18 · UX: no way to place a note at a chosen ratio from the anchor — CONFIRMED (admitted in TASKS T7.5b)
The user's own example ("place something at 3/2 above harmonic 5 → 10 and 15") works only when the 3/2 happens to be a
harmonic guide after renumbering, i.e. it cannot be drawn: the guides are whole harmonics of the current F, and 15/2 is
not one. Paste / document only. Notes chained through another anchored note are not numbered. **Fix:** "Add Note at
Ratio…" on a note (field "3/2"), and Set Pitch accepting a ratio relative to the anchor; number chains.

### M19 · UX: bends are baked (Q289) and so are recognised by shape — CONFIRMED
A bend aims at the neighbour's pitch at gesture time: move the neighbour, change the tuning, or paste the note
elsewhere and the glide lands on the old pitch, with no mark. H4 is the same root cause. For a tool whose point is
retuning chords, (b) "derived" is the right model; it deserves a task rather than staying an open question.

## The three UX changes I would make first

1. **Make Shift + drag safe and bends real.** A dead zone and a status line for detune, keep the note's identity with an
   offset instead of converting to Cents; store bends as bends (Q289 b). This removes H4, H5 and M19 together.

3. **Give the feature visible entry points.** A JI tool button and menu entry, "Add Note at Ratio…" from the anchor,
   Walk in the object menu, a marker on the anchor note; and stop double-click inside a box from entering it.
